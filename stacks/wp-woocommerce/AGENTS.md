## Tech Stack

**Используем:**

| Слой              | Технология                                        | Почему                                                            |
| ----------------- | ------------------------------------------------- | ----------------------------------------------------------------- |
| CMS / Backend     | WordPress 6.x (PHP 8.1+)                          | Зрелая CMS, родные API, работает на любом shared-хостинге         |
| БД                | MySQL 8+ / MariaDB 10.6+                          | Стандарт WordPress, доступно в OpenServer и на shared-хостинге    |
| Тема              | Кастомная тема на базе болванки (`starter-theme`) | Полный контроль над разметкой и скоростью, без конструкторов      |
| Метаполя / опции  | Redux Framework (metaboxes / options)             | Единый инструмент для кастомных полей и повторителей              |
| Стили             | Bootstrap 5 (только сетка `row/col`) + BEM (`.lp-*` или префикс проекта) | Предсказуемая сетка, без сборщиков и CSS Grid-утилит |
| JS                | jQuery (из ядра WP) + vanilla JS (`main.js`)      | Без npm, Webpack, Vite и лишних зависимостей                      |
| Ассеты            | Self-hosted локально в теме                       | Никаких внешних CDN                                               |
| SEO / GEO         | SEO-плагин (Yoast / Rank Math / SEOPress) + `llms.txt` | Плагин владеет мета-тегами и sitemap, тема — структурой HTML |
| Code style        | WordPress Coding Standards (WPCS)                 | Единый стандарт PHP/WP (`phpcs.xml.dist`)                         |
| Локальная среда   | OpenServer (Apache/Nginx + PHP 8.1+ + MySQL)      | Совпадает с целевым shared-хостингом                              |

**Дизайн-токены и вёрстка (Stage 1):** если в проекте приложена готовая статическая вёрстка (`00-input/design/`) и/или `direction.md`, токены переносятся в блок `:root` файла `style.css` темы, а HTML-секции переносятся в `template-parts/` с соблюдением правил SEO (см. `.docs/rules/seo.md`).

**Окружение (допущение — подтвердить):** локально OpenServer (PHP 8.1+, MySQL/MariaDB), продакшен — shared-хостинг (без root-доступа, без Node.js, без системного Redis/Supervisor).

**Не используем — никогда:**

- Конструкторы страниц (Elementor, WPBakery, Divi, Gutenberg-комбайны вместо шаблонов темы)
- ACF (для кастомных полей и повторителей используется Redux Framework)
- Сборщики фронтенда (npm, Webpack, Vite, Gulp, Sass-компиляция в рантайме)
- Внешние CDN для CSS, JS и шрифтов (Google Fonts CDN, jsDelivr, cdnjs и т.п.)
- Сырые подключения PDO или `mysqli_*` напрямую в обход `$wpdb`
- Установку новых сторонних плагинов без записи решения в `.docs/dev-log.md`

## Ключевые правила проекта

Нумерация `CORE-N` — правила ядра. Правила пакетов имеют свои префиксы (см. «Правила пакетов»). При конфликте с кодом побеждает правило.

1. **CORE-1.** Всегда используй нативные WordPress API вместо самописных реализаций (`WP_Query`, `get_template_part()`, Settings/Options API, REST API, `wp_mail()`). Не усложняй архитектуру без необходимости.
2. **CORE-2.** Никакой бизнес-логики в шаблонах (`*.php` в корне темы и `template-parts/`). `functions.php` используется только для хуков, фильтров, подключений `require` и инициализации. Вся бизнес-логика темы живёт в `inc/` по принципу «один файл = одна ответственность».
3. **CORE-3.** Логика плагинов никогда не кладётся в тему. Кастомный функционал, не привязанный к оформлению (CPT, интеграции, расчёты, свои таблицы), выносится в отдельный плагин с корректным заголовком, защитой `ABSPATH` и уникальным префиксом функций, хуков, констант и классов.
4. **CORE-4.** Весь вывод данных в шаблонах всегда экранируется (`esc_html`, `esc_attr`, `esc_url`, `wp_kses_post`). Вывод неэкранированных данных запрещён при любых обстоятельствах.
5. **CORE-5.** Все входные данные (`$_POST`, `$_GET`, `$_REQUEST`, AJAX, REST API) всегда валидируются и санитизируются (`sanitize_text_field`, `absint`, `sanitize_email`, `wp_unslash`) до использования. Сырые суперглобальные массивы напрямую никогда не используются.
6. **CORE-6.** Все формы и изменяющие состояние действия защищены WordPress nonces (`wp_nonce_field` + `wp_verify_nonce` / `check_ajax_referer`). Все привилегированные действия и эндпоинты проверяют права через `current_user_can()`.
7. **CORE-7.** Сырые PDO и `mysqli` запрещены. Любые прямые SQL-запросы выполняются только через `$wpdb` с `$wpdb->prepare()`. Конкатенация переменных в SQL-строку запрещена даже внутри `$wpdb->prepare()`.
8. **CORE-8.** Стили и скрипты подключаются только через `wp_enqueue_style()` и `wp_enqueue_script()` в хуке `wp_enqueue_scripts` с явным `$version` (`filemtime()` или константа версии темы) и `get_stylesheet_directory_uri()`. Прямые теги `<link>` и `<script>` в шаблонах и любые внешние CDN запрещены.
9. **CORE-9.** Переиспользуемая разметка выносится в `template-parts/` и подключается через `get_template_part()` с передачей данных третьим аргументом (`$args`, WP 5.5+) или `set_query_var()`. Все пользовательские строки интерфейса проходят через i18n-функции (`__()`, `_e()`, `esc_html__()`, `esc_attr__()`).
10. **CORE-10.** Секреты (доступы к БД, API-ключи, токены) никогда не хранятся в коде темы/плагинов и не коммитятся в git — только `wp-config.php` / локальный конфиг (`wp-config-local.php` в `.gitignore`). На проде `WP_DEBUG_DISPLAY` всегда `false`.
11. **CORE-11.** SEO-плагин владеет `<title>`, meta description, canonical, robots meta, OG/Twitter, базовым JSON-LD, sitemap и `robots.txt`. Тема вызывает `add_theme_support( 'title-tag' )`, `wp_head()`, `wp_body_open()` и никогда не дублирует эти теги и не создаёт физические `sitemap.xml` / `robots.txt` в корне.
12. **CORE-12.** Кастомные поля и повторители реализуются через Redux Framework (metaboxes / options), не через ACF. В шаблонах значения метаполей всегда читаются с безопасным значением по умолчанию и экранируются при выводе.
13. **CORE-13.** Верстка строится на Bootstrap 5 (только сетка `row/col`, без CSS Grid-утилит) + BEM-классах (`.lp-*` или префикс проекта), JS — jQuery из WP core + vanilla JS в `main.js`, без npm/сборщиков. Дизайн-токены (`:root`) хранятся в `style.css`.
14. **CORE-14.** Код соответствует WordPress Coding Standards (WPCS) и PHP 8.1+. Перед завершением задачи все изменённые PHP-файлы проходят `php -l` (и `phpcs`, если установлен) без ошибок, а `wp-content/debug.log` не содержит новых warnings/notices.

## Архитектура

```
wp-content/
├── themes/<theme-slug>/              → кастомная тема (в стартере — starter-theme, переименовать в Фазе 0)
│   ├── style.css                     → шапка темы + дизайн-токены :root + базовые стили

│   ├── header.php, footer.php        → каркас с wp_head(), wp_body_open(), wp_footer() (CORE-11)
│   ├── front-page.php, page.php,     → шаблоны WP (только вывод, без бизнес-логики)
│   │   single.php, archive.php, 404.php
│   ├── inc/                          → бизнес-логика темы, по файлу на ответственность (CORE-2)
│   │   ├── setup.php                 → add_theme_support, меню, размеры изображений
│   │   ├── assets.php                → wp_enqueue_style / wp_enqueue_script (CORE-8)
│   │   ├── redux-config.php          → опции и метабоксы Redux Framework (CORE-12)
│   │   ├── ajax.php                  → AJAX-обработчики с nonce и санитизацией (CORE-5, CORE-6)
│   │   └── template-tags.php         → хелперы вывода для шаблонов
│   ├── template-parts/               → переиспользуемые блоки разметки (CORE-9)
│   ├── assets/                       → self-hosted CSS, JS, шрифты, изображения (CORE-8)
│   │   ├── css/vendor/               → bootstrap.min.css и др. локальные библиотеки
│   │   ├── js/vendor/                → bootstrap.bundle.min.js и др. локальные библиотеки
│   │   ├── js/main.js                → клиентский JS проекта (jQuery + vanilla JS)
│   │   ├── fonts/                    → локальные шрифты
│   │   └── img/                      → изображения темы
│   ├── languages/                    → переводы .pot/.po/.mo
│   └── phpcs.xml.dist                → конфиг WordPress Coding Standards
└── plugins/<project-plugin>/         → проектный плагин (если включён пакет custom-plugin, CORE-3)

llms.txt                              → статический файл в корне сайта (если нужен по SEO/GEO)
wp-config-local.php                   → локальные доступы OpenServer (в .gitignore, CORE-10)
```

Ядро WordPress (`wp-admin/`, `wp-includes/`, корневые `wp-*.php`), `wp-content/uploads/` и сторонние плагины не хранятся в git (см. `.gitignore`). Каждый включённый пакет может добавить свои каталоги (например, `woocommerce/` внутри темы) — они описаны в его блоке «Правила».

## Правила по слоям

| Слой                  | Отвечает за                                        | Не делает                                            |
| --------------------- | -------------------------------------------------- | ---------------------------------------------------- |
| `functions.php`       | Регистрация хуков, фильтров, `require` из `inc/`   | Бизнес-логика, SQL, HTML-разметка                    |
| `inc/*.php`           | Бизнес-логика темы, AJAX/REST, настройки Redux     | Прямой вывод неэкранированного HTML, сырой PDO       |
| Шаблоны темы (`*.php`) | Сборка страницы из `template-parts/`, цикл WP      | Бизнес-логика, `$_POST`/`$_GET`, прямые SQL-запросы  |
| `template-parts/`     | Переиспользуемые фрагменты разметки (`$args`)      | Запросы в БД, глобальная бизнес-логика               |
| Проектный плагин      | Независимая от темы логика, CPT, интеграции, БД    | Вёрстка темы (кроме подключаемых шаблонов с оверрайдом) |
| `assets/js/main.js`   | Интерактив UI, отправка AJAX с nonce из `wp_localize_script` | Хардкод URL сайта, бизнес-валидация вместо сервера |

## Безопасность

Базовые правила — `CORE-4`, `CORE-5`, `CORE-6`, `CORE-7`, `CORE-10`. Детали и примеры — `.docs/rules/wordpress.md`. Расширения для WooCommerce, заявок и интеграций — в блоках включённых пакетов.

- В каждом PHP-файле темы/плагина при прямом доступе — проверка `if ( ! defined( 'ABSPATH' ) ) { exit; }`
- Все формы и AJAX-запросы — с проверкой nonce и прав (`current_user_can()` для защищённых операций)
- На проде `WP_DEBUG_DISPLAY = false`, ошибки пишутся только в `wp-content/debug.log` (недоступен по HTTP)
- Никакого редактирования ядра WordPress и сторонних плагинов — изменения только через хуки, фильтры и шаблоны темы

## AI Rules (для агента)

- Перед задачей читать `TASK.md` и `phase-N.md`
- Работать только в scope текущего таска
- Не менять файлы вне scope
- Не рефакторить попутно
- Перечислять файлы, которые будут изменены
- Сначала анализ → план → список файлов → только потом код
- Для многошаговых тасков — на каждый шаг сразу указывать, чем он будет проверен (`php -l`, `phpcs`, ручная проверка в браузере на OpenServer, `view-source`, `wp-content/debug.log`, конкретный пункт DoD), а не только что сделать
- Не выдумывать несуществующие хуки, функции или поведение WordPress/WooCommerce/Redux — при сомнении проверять документацию
- Если требование противоречит WordPress best practices — объяснить почему и предложить безопасную альтернативу
- Не подгонять `.docs/prd.md` под написанный код: расхождение кода и требования — дефект реализации

### Поддержка документации проекта

- Изменения и решения фиксируй в `.docs/dev-log.md` — не версионируй `AGENTS.md` записями вида «v1.2 — добавлено…» внутри самого файла. `AGENTS.md` описывает текущее состояние, а не историю изменений
- Если правило уже описано в файле (`AGENTS.md`, `wordpress.md`, `database.md`) — обновляй его на месте. Не добавляй второе упоминание того же факта в другом разделе или файле
- WHY у неочевидного архитектурного решения — 1–2 строки прямо на месте. Если объяснение разрастается — выноси в `.docs/modules/<name>.md` или `.docs/dev-log.md`, а на месте оставляй короткую ссылку
- Состав пакетов и параметры проекта меняются только в `.docs/prd.md` → «Возможности», затем перегенерируются `AGENTS.md`, `database.md`, `dod-global.md`
