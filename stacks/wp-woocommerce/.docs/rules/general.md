## Общие принципы

- Предпочитай **нативные API WordPress** самописным решениям (`CORE-1`)
- **Не усложняй** (no overengineering): простое, читаемое и поддерживаемое решение всегда лучше «хитрого»
- Один файл = одна ответственность (`CORE-2`), избегай жёсткой связанности компонентов
- Объясняй решения простым и понятным языком
- Если требования или контекст неясны — **явно скажи об этом** и задай вопрос до написания кода, не угадывай
- Никаких магических чисел — именованные константы или опции (Redux / `wp_options`)
- Секреты никогда не хардкодить — только `wp-config.php` / `wp-config-local.php` (`CORE-10`)
- При правке существующего кода следуй его стилю. Удаляй только неиспользуемый код, появившийся из-за твоей правки; чужой мёртвый код рядом не трогай, а упомяни
- Пиши production-ready код; комментарии добавляй только там, где они реально проясняют «почему»
- Если требование противоречит best practices WordPress — объясни почему и предложи безопасную альтернативу

## HTML

- Семантическая разметка: `<main>`, `<section>`, `<article>`, `<nav>`, `<header>`, `<footer>`
- У секций стабильные смысловые `id` (для якорных ссылок и GEO-структуры)
- Доступность обязательна: осмысленный `alt` на контентных изображениях, `alt=""` на декоративных, `aria-*` и `role` где нужно
- Семантические таблицы и списки там, где данные табличные или списочные
- Никаких inline-стилей (`style="…"`) — только CSS-классы

## CSS и дизайн-токены

- **Bootstrap 5:** использовать **только сетку `row`/`col`** и базовые брейкпоинты, без CSS Grid-утилит
- **BEM:** кастомные классы с единым префиксом проекта (`.lp-*` при посадке из Stage 1 или префикс темы)
- **Дизайн-токены:** источник истины — `direction.md` (если проект идёт со статического Stage 1 из `00-input/design/`), реализованный как блок `:root` в `style.css` темы (`CORE-13`)
- **Self-hosted ассеты:** весь CSS, JS и шрифты лежат локально внутри темы (`assets/`), никаких внешних CDN (`CORE-8`)
- **Без сборщиков:** никаких npm, Webpack, Vite, Gulp или Sass-компиляции в проекте (`CORE-13`)
- `!important` не использовать (кроме крайних случаев переопределения стороннего виджета с комментарием)

## JavaScript

- **jQuery** (встроенный в ядро WordPress / в связке с Bootstrap 5) + **vanilla JS** в `assets/js/main.js`
- Без сборщиков и npm-зависимостей (`CORE-13`)
- Передача данных из PHP в JS (AJAX URL, nonces, локализация) — только через `wp_localize_script()` или `wp_add_inline_script()`, никогда через инлайновые `<script>` в шаблонах (`CORE-8`)
- Клиентская валидация улучшает UX, но никогда не заменяет серверную (`CORE-5`)
