# SEO / GEO на WordPress

Правила конкретизируют `CORE-11` из `AGENTS.md`.

## 1. Разделение ответственности: SEO-плагин vs Тема

**SEO-плагин (Yoast SEO / Rank Math / SEOPress) владеет:**
- `<title>`
- `<meta name="description">`
- `<link rel="canonical">`
- `robots` meta (`noindex`, `nofollow`)
- Open Graph и Twitter Cards
- базовым JSON-LD (`Organization`, `WebSite`, `BreadcrumbList`)
- динамическим `sitemap.xml`
- виртуальным `robots.txt`

**Тема НИКОГДА не выводит эти теги сама.**

**Тема обязана:**
- вызывать `add_theme_support( 'title-tag' )` в `inc/setup.php` (хук `after_setup_theme`)
- вызывать `wp_head()` непосредственно перед `</head>` в `header.php`
- вызывать `wp_body_open()` сразу после открывающего `<body>` в `header.php`
- вызывать `wp_footer()` непосредственно перед `</body>` в `footer.php`
- не содержать захардкоженных `<title>`, `<meta name="description">`, `canonical` и OG-тегов в `header.php`

## 2. Перенос из статической вёрстки (Stage 1)

- Статический `<head>` и JSON-LD из Stage 1 (`00-input/design/`) — это **только источник текстов** для заполнения полей в настройках SEO-плагина. Они **не копируются** в `header.php` или шаблоны темы.

## 3. Кастомный JSON-LD

- Добавлять кастомный JSON-LD (`FAQPage`, `Person`, `LocalBusiness` и др.) в коде темы допустимо **только** если SEO-плагин не умеет генерировать этот тип разметки.
- Перед добавлением обязательно проверь настройки схемы в SEO-плагине и исходный код страницы (`view-source`), чтобы не создать дублирующиеся типы `@type`.
- Разметка `FAQPage` выводится **только** при наличии видимого пользователю FAQ-блока на той же странице, а тексты вопросов и ответов должны совпадать с видимыми.

## 4. Файлы в корне сайта

- **Не создавать** физические `sitemap.xml` и `robots.txt` в корне сайта — ими управляет SEO-плагин.
- `llms.txt` — **статический файл** в корне сайта (создаётся, если предусмотрен проектом/ТЗ).

## 5. Структура контента (зона ответственности темы)

SEO-плагин не исправляет HTML-разметку внутри страницы — за неё отвечает тема:
- ровно один `<h1>` на странице
- логичная иерархия заголовков (`<h2>`, `<h3>` без пропусков уровней)
- принцип **answer-first** для ключевых информационных блоков
- стабильные смысловые `id` у секций
- семантические таблицы (`<table>`, `<thead>`, `<th>`) и списки (`<ul>`, `<ol>`)
- осмысленный `alt` у всех контентных изображений (`alt=""` у декоративных)
- важный для индексации контент присутствует в HTML-ответе сервера без JS

## 6. Обязательная проверка после посадки (`view-source`)

После посадки любой страницы или шаблона проверь исходный код (`view-source:` или `curl`):
- [ ] ровно один тег `<title>`
- [ ] ровно один `<link rel="canonical">`
- [ ] нет дублирующихся типов JSON-LD (`@type`)
- [ ] ровно один `<h1>` и корректная вложенность заголовков
