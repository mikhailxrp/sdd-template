# Global Definition of Done

Эти критерии применяются к каждому таску.
Проверяй вручную на OpenServer перед тем как считать задачу выполненной.

**Всегда критичны разделы «Данные» и «Безопасность»:** непройденный пункт из них = таск не принят, без исключений. Остальные разделы проверяются по затронутому скоупу: если таск не касается пункта, он отмечается как неприменимый, а не пропускается молча.

Блоки включённых пакетов (WooCommerce, заявки, проектный плагин, оплаты и т.д.) лежат в конце файла, в разделе «Блоки пакетов». Если пакет не включён, его блока здесь нет. Блок с пометкой «Критично» приравнивается к разделам «Данные» и «Безопасность»: непройденный пункт = таск не принят.

## UI

- [ ] Страница открывается на OpenServer без PHP-ошибок и предупреждений
- [ ] Нет сломанной вёрстки, горизонтального скролла и наложения блоков
- [ ] Страница корректно отображается на мобильном (320px+)
- [ ] Используется только сетка Bootstrap 5 (`row/col`, без CSS Grid-утилит) и BEM-классы; нет inline-стилей и внешних CDN (`CORE-8`, `CORE-13`)
- [ ] Если таск затрагивает админку (Redux-метабоксы, CPT, настройки): поля открываются, сохраняются, значения по умолчанию и повторители не ломаются

## Данные

- [ ] После отправки формы / сохранения метаполей — данные корректно сохраняются в БД и отображаются после перезагрузки страницы
- [ ] Пользователю выводится понятное уведомление об успехе или ошибке
- [ ] Данные других пользователей недоступны: права проверяются через `current_user_can()` и проверку владельца сущности, а не только скрытием кнопки в шаблоне (`CORE-6`)
- [ ] Все пользовательские и AJAX-данные санитизируются до записи (`sanitize_text_field`, `absint`, `sanitize_email`, `wp_unslash`) (`CORE-5`)
- [ ] Любые кастомные SQL-запросы выполняются только через `$wpdb->prepare()` без конкатенации переменных (`CORE-7`); для стандартных сущностей используются нативные WP API (`CORE-1`)
- [ ] При создании/обновлении кастомных таблиц используется `dbDelta()` с проверкой версии схемы, без ручного DDL на проде

## Безопасность

- [ ] Все формы и изменяющие состояние AJAX/POST-действия защищены nonce (`wp_nonce_field` + `wp_verify_nonce` / `check_ajax_referer`) (`CORE-6`)
- [ ] Все привилегированные действия (админка, REST API `permission_callback`, AJAX `wp_ajax_*`) проверяют `current_user_can()` (`CORE-6`); публичные `wp_ajax_nopriv_*` строго ограничены публичными сценариями
- [ ] Весь вывод в шаблонах экранирован (`esc_html`, `esc_attr`, `esc_url`, `wp_kses_post`); неэкранированный вывод отсутствует (`CORE-4`)
- [ ] Нигде не используются сырые `$_POST`, `$_GET`, `$_REQUEST` без `wp_unslash()` + санитизации и валидации (`CORE-5`)
- [ ] Нет прямых подключений PDO или `mysqli_*`; все SQL-запросы проходят через `$wpdb->prepare()` (`CORE-7`)
- [ ] Каждый PHP-файл темы/плагина защищён от прямого доступа (`if ( ! defined( 'ABSPATH' ) ) { exit; }`) (`CORE-3`)
- [ ] Загрузка пользовательских файлов (если есть) идёт через `wp_handle_upload()` / `wp_check_filetype_and_ext()` с проверкой MIME-типа и размера; исполняемые файлы (`.php`, `.phtml`) отклоняются
- [ ] Редиректы используют `wp_safe_redirect()` вместо `wp_redirect()` для внутренних URL (защита от Open Redirect)
- [ ] Путь к файлам никогда не собирается из пользовательского ввода (защита от Path Traversal)
- [ ] В репозитории нет секретов: `wp-config.php`, `wp-config-local.php`, `.env` в `.gitignore`; на проде `WP_DEBUG_DISPLAY = false` (`CORE-10`)
- [ ] Служебные файлы (`wp-config.php`, `wp-content/debug.log`, `.git/`, бэкапы `.sql`/`.zip`) недоступны по прямому HTTP-запросу на сервере
- [ ] Публичная форма (если не отключено явно в `NFR-SEC-*` ТЗ) защищена от ботов: honeypot-поле (скрыто CSS `display:none`), проверка минимального времени заполнения (2–3 сек) и валидация nonce; при срабатывании антиспама возвращается нейтральный ответ «Спасибо» без создания записи и отправки писем

## Производительность

- [ ] Нет тяжёлых запросов внутри циклов (N+1 по `get_post_meta` / `WP_Query` без `update_post_meta_cache` или `no_found_rows => true` где пагинация не нужна)
- [ ] Списки записей/товаров выводятся с пагинацией (`posts_per_page`), никогда `posts_per_page => -1` на больших выборках
- [ ] Стили и скрипты подключены через `wp_enqueue_style` / `wp_enqueue_script` с `$version` для cache busting; тяжёлые скрипты подключены в footer (`in_footer => true`) (`CORE-8`)
- [ ] Нет внешних запросов к CDN (шрифты, Bootstrap, jQuery — локально) (`CORE-8`)

## SEO и GEO

- [ ] В `view-source` страницы ровно один `<title>`, один `<link rel="canonical">`, нет дублей мета-тегов и дублей типов JSON-LD (`CORE-11`)
- [ ] Тема вызывает `add_theme_support( 'title-tag' )`, `wp_head()` перед `</head>` и `wp_body_open()` после `<body>`; в `header.php` нет захардкоженных `<title>`, meta description, canonical и OG-тегов (`CORE-11`)
- [ ] На странице ровно один `<h1>`; иерархия `<h2>`/`<h3>` соответствует смысловой структуре, без пропусков уровней ради размера шрифта
- [ ] У каждого контентного `<img>` есть осмысленный `alt`; у декоративных — `alt=""`
- [ ] Ключевой контент присутствует в HTML-ответе сервера без выполнения JS (`curl` или `view-source`)
- [ ] В корне сайта нет физических файлов `sitemap.xml` и `robots.txt` (ими управляет SEO-плагин); `llms.txt` — статический файл в корне, если предусмотрен проектом (`CORE-11`)
- [ ] Кастомный JSON-LD (`FAQPage`, `Person`, `LocalBusiness`) добавлен только если его не генерирует SEO-плагин; `FAQPage` выводится только при наличии видимого FAQ-блока на странице

## Формы и валидация

- [ ] Пустые обязательные поля и некорректный ввод валидируются на сервере (не только HTML5 `required` / JS) и возвращают понятное сообщение об ошибке
- [ ] При ошибке валидации пользователь видит, какое поле заполнено неверно, а введённые данные не теряются (где применимо)

## Код

- [ ] Нет ошибок в консоли браузера
- [ ] Нет новых PHP warnings/notices/fatals в `wp-content/debug.log` после прохождения сценария таска (`CORE-14`)
- [ ] `php -l` проходит без ошибок на всех изменённых PHP-файлах (`CORE-14`)
- [ ] `phpcs` (WPCS по `phpcs.xml.dist`) проходит без ошибок (если установлен в окружении) (`CORE-14`)
- [ ] Бизнес-логика лежит в `inc/` или проектном плагине, а не в `functions.php` и не в шаблонах (`CORE-2`, `CORE-3`)
- [ ] Все пользовательские строки в шаблонах и PHP обёрнуты в `__()`, `_e()`, `esc_html__()`, `esc_attr__()` с text-domain темы/плагина (`CORE-9`)
- [ ] Не использованы запрещённые инструменты (ACF, page builders, npm/сборщики, CDN, сырой PDO/mysqli)
- [ ] Новый сторонний плагин добавлен только вместе с записью решения в `.docs/dev-log.md`
