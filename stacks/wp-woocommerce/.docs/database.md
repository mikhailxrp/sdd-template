# Схема БД и модель данных WordPress

> Этот файл — описание модели данных проекта: стандартные таблицы WordPress, типы записей (CPT), таксономии, метаполя Redux Framework и кастомные таблицы MySQL/MariaDB.
> Агент читает его при планировании тасков, связанных с данными.
> Прямые запросы к БД допускаются **только** через `$wpdb->prepare()` (`CORE-7`). Для стандартных сущностей WP и WooCommerce используй нативные API (`WP_Query`, `get_post_meta`, WC CRUD API) (`CORE-1`).

СУБД: **MySQL 8+ / MariaDB 10.6+** (префикс таблиц `$wpdb->prefix`, по умолчанию `wp_`).

---

## Как устроен этот файл

Ниже — **ядро модели данных WordPress**: штатные таблицы и правила хранения контента/настроек темы (Redux Framework). Сущности и таблицы предметной области (WooCommerce, заявки, проектные кастомные таблицы) приходят из включённых пакетов и вставляются в раздел «Таблицы пакетов» командой `sdd-capabilities` из `.docs/prd.md` → «Возможности».

При адаптации под проект (`/sdd-schema`):

- в WordPress большинство сущностей реализуется через **Custom Post Types (CPT) + таксономии + метаполя (Redux)**, а не через отдельные SQL-таблицы;
- отдельная кастомная таблица (`dbDelta`) оправдана только для высоконагруженных/табличных данных (логи, заявки с фильтрацией, кэш синхронизации, связки с внешними ID), где `wp_postmeta` даёт медленные JOIN;
- каждая кастомная таблица описывается в разделе «Дополнительные таблицы» в формате `колонка | тип MySQL | назначение` с явными индексами и создаётся через `dbDelta()` в проектном плагине (`CORE-3`).

## Штатные таблицы ядра WordPress

Создаются и мигрируются самим WordPress. Руками не правятся, DDL к ним не применяется:

| Таблица | Назначение | API для работы |
|---------|------------|----------------|
| `wp_posts` | Записи (`post`), страницы (`page`), вложения (`attachment`), ревизии, меню, CPT | `WP_Query`, `wp_insert_post()`, `get_post()` |
| `wp_postmeta` | Метаполя записей и страниц (включая метабоксы Redux Framework) | `get_post_meta()`, `update_post_meta()`, Redux |
| `wp_terms`, `wp_term_taxonomy`, `wp_term_relationships` | Рубрики, метки и кастомные таксономии | `get_terms()`, `wp_set_object_terms()` |
| `wp_users`, `wp_usermeta` | Пользователи и их роли/права/метаполя | `WP_User`, `get_user_meta()`, `current_user_can()` |
| `wp_options` | Настройки сайта, опции темы (Redux Framework `opt_name`), транзиенты | `get_option()`, `update_option()`, `get_transient()` |
| `wp_comments`, `wp_commentmeta` | Комментарии (и отзывы товаров WooCommerce) | `get_comments()`, `wp_insert_comment()` |

## Настройки темы и метаполя (Redux Framework)

Опции темы хранятся в `wp_options` под единым ключом `opt_name` (задаётся в `inc/redux-config.php`), метабоксы страниц/CPT — в `wp_postmeta` (`CORE-12`).

| Группа / Экран | Тип хранения | Ключи полей | Назначение |
|----------------|--------------|-------------|------------|
| Общие настройки темы | Redux Options (`opt_name`) | < телефон, email, адрес, соцсети, логотип > | Вывод в шапке/подвале и контактах |
| Главная страница (`front-page.php`) | Redux Metaboxes (`page`) | < заполняется на `/sdd-schema` > | Секции и повторители главной страницы |

## Кастомные типы записей (CPT) и таксономии проекта

> Заполняется на шаге `/sdd-schema` по разделу модели данных ТЗ. Регистрация CPT и таксономий выносится в проектный плагин (`CORE-3`).

| CPT / Таксономия | Slug | Поддержка (`supports`) | Таксономии | Метаполя (Redux) |
|------------------|------|------------------------|------------|------------------|
| < пример: Кейсы > | < `case` > | < `title`, `editor`, `thumbnail` > | < `case_category` > | < клиент, год, галерея > |

## Дополнительные таблицы (кастомные SQL-таблицы проекта)

Не создаются по умолчанию. Добавляются на шаге `/sdd-schema`, только если `wp_posts` + `wp_postmeta` недостаточно. Создаются через `dbDelta()` при активации проектного плагина с версионированием схемы в `wp_options` (`<prefix>_db_version`).

| Таблица | Когда нужна |
|---------|-------------|
| `<prefix>_<entity>` | < описание, почему не CPT/meta > |
