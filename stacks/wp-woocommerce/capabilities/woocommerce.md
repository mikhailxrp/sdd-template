# Магазин WooCommerce

Подключает функциональность интернет-магазина на базе WooCommerce: каталог товаров (простые и вариативные), корзину, оформление заказа, личный кабинет покупателя, штатные способы доставки и оплаты из коробки.

## Параметры

| Параметр | Зачем | Пример |
|----------|-------|--------|
| Типы товаров | Простые, вариативные, виртуальные/скачиваемые | Простые + вариативные (размер, цвет) |
| Валюта и формат цены | Настройки WooCommerce и округление | RUB (₽), без копеек |
| Доставка из коробки | Штатные зоны доставки WC (плоская ставка, самовывоз, бесплатная от суммы) | Самовывоз + курьер по городу |
| Оплата из коробки | Штатные методы WC (при получении, банковский перевод) или внешний шлюз (`payments-ru`) | Оплата при получении (наличными/картой) |
| HPOS (High-Performance Order Storage) | Включён ли режим HPOS (по умолчанию в WC 8.2+ включён) | Включён (да) |
| Гостевой заказ | Разрешено ли оформление заказа без регистрации | Да |

## Правила

1. **WOO-1.** Вся работа с товарами, заказами, корзиной и покупателями выполняется **только через WooCommerce CRUD API** (`wc_get_product()`, `wc_get_order()`, `WC_Order`, `WC()->cart`). Прямые SQL-запросы к таблицам заказов и товаров и прямая запись в `wp_postmeta` в обход CRUD API запрещены — иначе ломается HPOS и кэш WooCommerce.
2. **WOO-2.** Тема объявляет поддержку WooCommerce через `add_theme_support( 'woocommerce' )` в `inc/setup.php` (и при необходимости `wc-product-gallery-zoom`, `wc-product-gallery-lightbox`, `wc-product-gallery-slider`).
3. **WOO-3.** Переопределение шаблонов WooCommerce допускается **только** копированием нужного файла в `woocommerce/` внутри темы, и только если задачу нельзя решить стандартными хуками `remove_action` / `add_action` / `add_filter`. Не копируй шаблоны WooCommerce «про запас».
4. **WOO-4.** Вся логика кастомизации WooCommerce (хуки каталога, поля чекаута, пересчёт корзины, фрагменты мини-корзины) живёт в `inc/woocommerce.php` (или `inc/woocommerce/*.php`), а не в `functions.php` и не в шаблонах (`CORE-2`).
5. **WOO-5.** Цены, скидки и суммы заказов рассчитываются средствами WooCommerce (`wc_format_decimal()`, `WC_Order::calculate_totals()`). Никогда не доверяй цене или сумме, присланной с клиента в `$_POST`/AJAX — итоговая сумма всегда пересчитывается на сервере из объектов `WC_Product`.
6. **WOO-6.** Скрипты и стили WooCommerce отключаются или дополняются только через штатные фильтры (`woocommerce_enqueue_styles`, `wp_enqueue_scripts`) (`CORE-8`). Отключать скрипты корзины/чекаута на страницах `is_cart()` / `is_checkout()` запрещено.
7. **WOO-7.** Доступ к заказам и личному кабинету проверяется через права и владельца заказа (`$order->get_customer_id() === get_current_user_id()` или `current_user_can( 'manage_woocommerce' )`) (`CORE-6`). Покупатель никогда не может открыть или изменить чужой заказ по ID.
8. **WOO-8.** Изменение статусов заказов идёт только через `$order->update_status( $new_status, $note )`, чтобы срабатывали штатные хуки, письма и учёт остатков WooCommerce.

## Каталоги

```
wp-content/themes/<theme-slug>/
├── inc/woocommerce.php          → хуки, фильтры, поля чекаута, AJAX-фрагменты корзины (WOO-4)
└── woocommerce/                 → точечные оверрайды шаблонов WC, только если хуков недостаточно (WOO-3)
```

## Таблицы БД

WooCommerce использует собственные таблицы (создаются и обновляются самим плагином; руками DDL не применяется) плюс `wp_posts` (`product`, `product_variation`) и `wp_terms` (`product_cat`, `product_tag`, `pa_*`):

| Таблица / Сущность | Назначение | API для работы |
|--------------------|------------|----------------|
| `wp_wc_orders`, `wp_wc_orders_meta`, `wp_wc_order_addresses` | Заказы в режиме HPOS (основное хранилище в WC 8.2+) | `wc_get_order()`, `WC_Order` (`WOO-1`) |
| `wp_woocommerce_order_items`, `wp_woocommerce_order_itemmeta` | Позиции заказа, доставка, купоны | `$order->get_items()` (`WOO-1`) |
| `wp_wc_product_meta_lookup` | Индексная таблица цен, SKU, остатков и рейтинга | `wc_get_product()`, `wc_get_products()` (`WOO-1`) |
| `wp_woocommerce_sessions` | Сессии корзин гостей | `WC()->session`, `WC()->cart` |

**Связи:**

```
wp_users ──< wp_wc_orders (customer_id)
wp_wc_orders ──< wp_woocommerce_order_items (order_id)
wp_posts (product) ──< wp_wc_product_meta_lookup (product_id)
```

## SEO

| Страница | schema.org | Обязательные поля | robots / sitemap |
|----------|------------|-------------------|------------------|
| Карточка товара | `Product` + `Offer` (генерирует WooCommerce / SEO-плагин — проверить `view-source` на дубли) | `name`, `image`, `price`, `priceCurrency`, `availability` | В sitemap, индексируется |
| Категория товаров | `BreadcrumbList` (SEO-плагин) | `canonical` без параметров фильтра/сортировки | В sitemap; фасетные фильтры с `noindex` или `canonical` на категорию |
| Корзина, чекаут, личный кабинет | — | — | `noindex, nofollow` (настройка SEO-плагина / WC), исключены из sitemap |

## DoD

**Критично: непройденный пункт = таск не принят.**

- [ ] Все операции с товарами и заказами идут через WC CRUD API (`wc_get_product`, `wc_get_order`), прямых SQL к таблицам заказов и `wp_postmeta` заказов нет (`WOO-1`)
- [ ] Сумма заказа и цены рассчитываются исключительно на сервере из `WC_Product`; подмена цены/суммы в запросе чекаута невозможна (`WOO-5`)
- [ ] Чужой заказ недоступен по прямому URL / ID (`/my-account/view-order/<чужой_id>/`) (`WOO-7`)
- [ ] Полный путь «каталог → карточка (включая вариации, если есть) → корзина → оформление заказа → страница благодарности → заказ в админке WC» проходит на OpenServer без ошибок в консоли и `wp-content/debug.log`
- [ ] Корзина, чекаут и личный кабинет закрыты от индексации (`noindex`), а в `view-source` карточки товара нет дублей schema `Product` (`CORE-11`)
- [ ] Переопределённые шаблоны в `woocommerce/` (если есть) актуальны для установленной версии WooCommerce (нет предупреждений в «WooCommerce → Статус → Шаблоны») (`WOO-3`)

## Проверки аудита

- `/audit-security`: попытка подменить цену/количество/способ доставки в запросе чекаута; доступ к чужому заказу в `/my-account/view-order/<id>/` от другого покупателя и гостя (`WOO-5`, `WOO-7`)
- `/audit-functional`: проверка полного сценария покупки (простой и вариативный товар, изменение количества, купон при наличии, расчёт доставки, создание заказа, письмо клиенту и админу, списание остатка)
- `/audit-integration`: совместимость с HPOS (нет прямых обращений к `shop_order` через `get_post_meta`/`WP_Query` по заказам, `WOO-1`); проверка статуса шаблонов WC
- `/audit-seo`: `noindex` на корзине/чекауте/кабинете, один `Product` JSON-LD на карточке товара, `canonical` на страницах с фильтрами/сортировкой

## Фазы

- **Фаза 0:** установка и базовая настройка WooCommerce (валюта, HPOS, страницы магазина/корзины/чекаута/кабинета, `add_theme_support('woocommerce')`).
- **Вертикальный срез 1:** каталог + карточка товара (простой/вариативный) + базовое добавление в корзину (можно показать клиенту).
- **Вертикальный срез 2:** корзина + чекаут + штатные доставка и оплата + уведомления о заказе (сквозной заказ работает до конца).
- **Ранний риск:** если включены внешние шлюзы (`payments-ru`, `shipping-ru`, `onec-sync`), их интеграция и тестовый обмен ставятся ранней фазой сразу после базового чекаута.

## С другими пакетами

- Если включён `custom-plugin`: бизнес-логика интеграций WooCommerce (синхронизация, кастомные статусы, расчёты доставки) выносится в проектный плагин, а в теме остаются только шаблоны и UI-хуки (`CORE-3`).
- Если включён `leads`: формы «Купить в 1 клик» / «Запросить КП» используют единый механизм валидации, nonce и антиспама из пакета `leads`.
