# Формы заявок и обратной связи

Подключает публичные формы захвата заявок (обратный звонок, запрос расчёта, контакты, форма на лендинге) с серверной валидацией, защитой от спама и отправкой уведомлений.

## Параметры

| Параметр | Зачем | Пример |
|----------|-------|--------|
| Список форм | Какие формы есть на сайте и какие поля обязательны | Обратный звонок (имя, телефон), Запрос КП (имя, телефон, email, комментарий) |
| Получатели уведомлений | Куда уходят заявки (email, Telegram-бот, CRM) | Email менеджера + дубль в админке WP |
| Хранение заявок в БД | Сохранять ли заявки в WP (CPT `lead` или таблица) помимо почты | Да, в закрытом CPT `lead` (непубличный) |
| Согласие на ПДн (152-ФЗ) | Чекбокс согласия и ссылка на политику конфиденциальности | Обязательный чекбокс перед отправкой |

## Правила

1. **LEAD-1.** Каждая публичная форма обрабатывается через AJAX (`wp_ajax_` + `wp_ajax_nopriv_`) или POST в `inc/ajax.php` (либо в проектном плагине при включённом `custom-plugin`), никогда напрямую в шаблоне (`CORE-2`).
2. **LEAD-2.** Каждый обработчик заявки проверяет nonce (`check_ajax_referer()` / `wp_verify_nonce()`), выполняет `wp_unslash()` + санитизацию всех полей (`CORE-5`, `CORE-6`) и возвращает структурированный JSON (`wp_send_json_success()` / `wp_send_json_error()`).
3. **LEAD-3.** Каждая публичная форма защищена от спама: honeypot-поле (скрытое CSS `display:none`, не только `hidden`), проверка минимального времени заполнения (2–3 секунды) и проверка nonce. При срабатывании антиспама сервер возвращает нейтральный успешный ответ «Спасибо, заявка принята», но не сохраняет запись и не отправляет уведомления.
4. **LEAD-4.** Отправка почты выполняется через нативный `wp_mail()` (`CORE-1`) с корректным `From` на домене сайта (для доставляемости на shared-хостинге) и `Reply-To` на email клиента (если указан), без инъекции заголовков (`\r`, `\n` вырезаются из `Subject` и заголовков).
5. **LEAD-5.** Если заявки сохраняются в WordPress (CPT `lead`), тип записи регистрируется с `public => false`, `publicly_queryable => false`, `show_ui => true`, чтобы заявки не индексировались и не открывались по URL снаружи.

## Каталоги

```
wp-content/themes/<theme-slug>/
├── inc/ajax.php                 → обработчики форм заявок (LEAD-1, LEAD-2)
└── template-parts/forms/        → переиспользуемые шаблоны форм (CORE-9)
```

## Таблицы БД

Хранение заявок (если включено в параметрах) использует штатные таблицы `wp_posts` (`post_type = 'lead'`, `public => false`) + `wp_postmeta` (телефон, email, источник/страница, UTM-метки). Отдельная SQL-таблица не требуется, если число заявок не превышает десятки тысяч.

**Связи:**

```
wp_posts (lead, public=false) ──< wp_postmeta (phone, email, source_url, utm)
```

## DoD

- [ ] Отправка формы с валидными данными создаёт запись (если включено хранение) и отправляет уведомление через `wp_mail()`, пользователь видит сообщение об успехе (`LEAD-2`, `LEAD-4`)
- [ ] Отправка без nonce или с поддельным nonce отклоняется сервером (`403` / JSON error) (`LEAD-2`, `CORE-6`)
- [ ] Заполнение honeypot-поля или отправка быстрее 2 секунд возвращает нейтральный «успех», но запись не создаётся и письмо не уходит (`LEAD-3`)
- [ ] Заявки в CPT `lead` недоступны по прямому URL снаружи и не попадают в sitemap (`LEAD-5`)
- [ ] Обязательные поля и чекбокс согласия на ПДн (если требуется) проверяются на сервере, а не только в JS (`CORE-5`)

## Проверки аудита

- `/audit-security`: отправка POST/AJAX без nonce, с XSS-пейлоадом в полях имени/комментария, с переносами строк `\r\n` в email/теме (header injection), проверка обхода антиспама (`LEAD-2`, `LEAD-3`, `LEAD-4`)
- `/audit-functional`: прохождение всех форм из ТЗ на десктопе и мобильном, проверка валидации пустых/некорректных полей, проверка доставки уведомления

## Фазы

- Реализуется одной компактной фазой (или вместе с посадкой главной/контактной страницы), с проверкой реальной отправки почты на OpenServer (лог писем OpenServer `userdata/temp/email/`).

## С другими пакетами

- Если включён `custom-plugin`: регистрация CPT `lead` и обработчик заявок выносятся в проектный плагин (`CORE-3`).
- Если включён `woocommerce`: формы «Купить в 1 клик» / «Уточнить наличие» используют те же правила валидации и антиспама (`LEAD-2`, `LEAD-3`).
