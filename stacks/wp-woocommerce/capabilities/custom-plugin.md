# Проектный функциональный плагин

Выносит независимую от оформления бизнес-логику проекта (CPT, таксономии, кастомные таблицы БД, внешние интеграции, шорткоды/REST-эндпоинты) в отдельный плагин `wp-content/plugins/<project-plugin>/`, чтобы смена темы не ломала данные и работу сайта.

## Параметры

| Параметр | Зачем | Пример |
|----------|-------|--------|
| Slug плагина | Имя папки, главного файла и text-domain | `myproject-core` |
| Префикс кода | Уникальный префикс функций, констант, хуков и таблиц | `myproject_` / `MYPROJECT_` |
| Что выносится в плагин | CPT, таксономии, кастомные таблицы, интеграции | CPT «Кейсы», таблица логов, REST API |

## Правила

1. **PLUG-1.** Главный файл `wp-content/plugins/<slug>/<slug>.php` содержит стандартный заголовок WordPress Plugin Header (`Plugin Name`, `Version`, `Text Domain`, `Requires PHP: 8.1`) и защиту `if ( ! defined( 'ABSPATH' ) ) { exit; }` в каждом PHP-файле (`CORE-3`).
2. **PLUG-2.** Все функции, классы/неймспейсы, константы, опции `wp_options` и пользовательские хуки плагина используют единый уникальный префикс проекта, зафиксированный в `.docs/prd.md` (`CORE-3`).
3. **PLUG-3.** Регистрация CPT, таксономий и кастомных ролей выполняется в плагине. При активации (`register_activation_hook`) выполняется `flush_rewrite_rules()` (после регистрации CPT) и установка/обновление таблиц; `flush_rewrite_rules()` никогда не вызывается на каждом запросе `init`.
4. **PLUG-4.** Создание и обновление кастомных таблиц БД выполняется только через `dbDelta()` с проверкой версии схемы в `wp_options` (`<prefix>_db_version`) и префиксом `$wpdb->prefix` (`CORE-7`).
5. **PLUG-5.** Логика плагина не зависит от конкретной темы: если плагин выводит разметку (шорткод/блок), он позволяет переопределить шаблон из активной темы через `locate_template()`.

## Каталоги

```
wp-content/plugins/<project-plugin>/
├── <project-plugin>.php         → заголовок плагина, константы, хуки активации/деактивации (PLUG-1)
├── includes/                    → модули по ответственности (CPT, DB, REST, интеграции)
│   ├── class-activator.php      → register_activation_hook, dbDelta, flush_rewrite_rules (PLUG-3, PLUG-4)
│   └── ...
└── templates/                   → шаблоны по умолчанию (переопределяемые в теме, PLUG-5)
```

> Не забудь раскомментировать `!wp-content/plugins/<project-plugin>/` в `.gitignore`, чтобы проектный плагин отслеживался в git.

## Таблицы БД

Кастомные таблицы плагина описываются в `.docs/database.md` → «Дополнительные таблицы» на шаге `/sdd-schema` и создаются через `dbDelta()` в `class-activator.php` (`PLUG-4`). Версия схемы хранится в `wp_options` под ключом `<prefix>_db_version`.

**Связи:**

```
wp_options (<prefix>_db_version) ──> контроль версии кастомных таблиц плагина (dbDelta)
```

## DoD

- [ ] Главный файл плагина имеет корректный Plugin Header, все файлы защищены `ABSPATH` и используют единый префикс (`PLUG-1`, `PLUG-2`, `CORE-3`)
- [ ] Плагин чисто активируется и деактивируется в админке WP без PHP warnings/notices в `wp-content/debug.log` (`CORE-14`)
- [ ] `flush_rewrite_rules()` вызывается только при активации/деактивации, не на каждом `init` (`PLUG-3`)
- [ ] Кастомные таблицы (если есть) создаются через `dbDelta()` с `$wpdb->prefix` и версионируются в `wp_options` (`PLUG-4`)
- [ ] Плагин добавлен в исключения `.gitignore` и отслеживается в репозитории

## Проверки аудита

- `/audit-security`: проверка `ABSPATH` во всех PHP-файлах плагина, `permission_callback` в кастомных REST-эндпоинтах, `$wpdb->prepare()` во всех запросах к кастомным таблицам (`CORE-6`, `CORE-7`)
- `/audit-integration`: активация/деактивация плагина и переключение темы — данные (CPT, кастомные таблицы) не теряются, сайт не падает с fatal error (`PLUG-5`)

## Фазы

- **Фаза 0:** создание скелета плагина, активация, добавление в `.gitignore`.
- Далее каждый CPT / кастомная таблица / интеграция добавляется в рамках соответствующей функциональной фазы.

## С другими пакетами

- Если включён `woocommerce`: плагин проверяет наличие класса `WooCommerce` (`class_exists( 'WooCommerce' )`) перед регистрацией WC-хуков, чтобы не вызывать fatal error при деактивации WooCommerce.
- Если включён `leads`: регистрация CPT `lead` и обработчик заявок размещаются в проектном плагине.
