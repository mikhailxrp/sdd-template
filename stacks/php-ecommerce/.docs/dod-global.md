# Global Definition of Done

Эти критерии применяются к каждому таску.
Проверяй вручную перед тем как считать задачу выполненной.

---

## UI
- [ ] Страница открывается без ошибок
- [ ] Нет сломанной вёрстки
- [ ] Страница корректно отображается на мобильном (320px+)

## Данные
- [ ] После отправки формы — запись появляется в БД
- [ ] Выводится уведомление об успехе или ошибке
- [ ] Данные других пользователей недоступны (изоляция по user_id)
- [ ] Пользователь не может увидеть или изменить чужой заказ/корзину,
      даже подставив чужой id в URL
- [ ] Денежные операции из нескольких шагов (заказ + списание остатка)
      либо проходят целиком, либо откатываются — не бывает
      наполовину применённых
- [ ] Списание остатка защищено от гонки при параллельных запросах —
      условный `UPDATE ... WHERE stock_quantity >= :qty` или
      `SELECT ... FOR UPDATE`, а не «прочитать, потом обновить»
      (голая транзакция сама по себе от гонки не защищает)

## Безопасность
- [ ] Незалогиненный пользователь не может открыть защищённую страницу
- [ ] Если страница/действие только для админа — проверяется
      `role = 'admin'`, а не только факт логина (обычный покупатель не
      должен попасть в админку, зная URL)
- [ ] Вывод данных в Views через htmlspecialchars()
- [ ] Формы с POST имеют CSRF-токен: поле выведено через `csrfField()`
      **и** контроллер вызывает `requireCsrf()` /
      `verifyCsrfToken()` до изменения данных — само по себе поле в
      HTML ничего не проверяет
- [ ] Цена и остаток товара пересчитываются на сервере из БД, а не
      берутся из данных, присланных клиентом (корзина, чекаут)
- [ ] Login и чекаут ограничены по частоте попыток —
      `tooManyAttempts()` / `hitRateLimit()` / `clearRateLimit()`
      (проверить вручную серией быстрых повторных запросов)
- [ ] Если таск загружает файлы (фото товара и т.п.): расширение и
      MIME-тип проверены на сервере по содержимому файла, а не по
      имени; размер ограничен; файл кладётся в `public/uploads/...`;
      `public/uploads/.htaccess` не ослаблен и не удалён
- [ ] Логин/регистрация/восстановление пароля не показывают, что
      именно неверно — «неверный email или пароль», не «такого
      пользователя не существует» (иначе перебором узнают, кто
      зарегистрирован)
- [ ] После успешного логина вызван `regenerateSession()`, а не сырой
      `session_regenerate_id()`
- [ ] Cookie сессии и security-заголовки не переопределены и не
      ослаблены вручную в контроллере (настроены централизованно в
      `ensureSessionStarted()` / `sendSecurityHeaders()`)

## Производительность
- [ ] Новый запрос к products/orders с фильтром, поиском или
      сортировкой — под него есть индекс в `.docs/database.md` (не
      полагаемся на полный скан таблицы)
- [ ] Списки товаров/заказов выводятся через пагинацию, а не одним
      запросом без LIMIT

## Формы и валидация
- [ ] Пустая форма не отправляется — поля подсвечиваются
- [ ] Некорректные данные — поля подсвечиваются с ошибкой

## Код
- [ ] Нет ошибок в консоли браузера
- [ ] Нет PHP ошибок и warnings (проверить storage/logs/app.log)
- [ ] Нет SQL в Controllers и Views
- [ ] Нет неиспользуемых переменных/импортов, которые появились
      из-за этого таска (предсуществующий мёртвый код рядом — не в
      скоупе; если заметил, просто упомяни)
- [ ] Деньги нигде не хранятся и не считаются как float
- [ ] Если таск добавляет/меняет чистую логику без обращения к БД
      (Core-хелперы, Router, расчёты над массивами) — есть unit-тест
      в `tests/Unit/` (`composer test`); автотесты дополняют ручную
      проверку, а не заменяют её для UI/Views и DB-потоков
