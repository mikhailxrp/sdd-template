## Универсальные

- Один файл = одна ответственность
- Ошибки обрабатывать явно (try/catch там, где есть что делать с ошибкой; запасное состояние интерфейса)
- Никаких магических чисел — именованные константы или значения из `config/`
- Простое лучше хитрого: если для понимания нужен комментарий — перепиши
- Секреты никогда не хардкодить — только `.env` (CORE-6)
- Перед написанием кода убедись, что задача понятна полностью
- Если задача неясна — задай ОДИН вопрос до начала кода
- Проговаривай допущения вслух, даже если не заблокирован; если у задачи больше одной разумной трактовки — покажи варианты, не выбирай молча
- Если существует более простой подход, чем запрошенный, скажи об этом до написания кода, не строй сразу более сложный
- При правке существующего кода следуй его стилю, даже если сделал бы иначе. Удаляй только импорты и переменные, которые стали ненужными из-за ТВОЕЙ правки; чужой мёртвый код рядом не чисти, а упомяни
- Перед написанием кода с любой библиотекой или внешним API (Laravel, Livewire, Filament, Tailwind, провайдеры почты/SMS/LLM и т.д.) всегда получай актуальную документацию через Context7

## Данные и статусы

- Деньги никогда не `float`. Хранить как `DECIMAL` или как целое в минимальных единицах (копейки); выбор делается один раз на проект и фиксируется в `.docs/database.md`. Арифметику над ценами не выполнять приведением к `float`. Форматирование — только при выводе (Blade, Filament)
- Сущности со статусом (заявка, заказ и т.п.): статус — backed enum. Смена статуса идёт только через одну Action, которая проверяет допустимость перехода (таблица переходов описана в `.docs/prd.md` или в модуле). Прямой `$model->update(['status' => …])` из контроллеров, Livewire, Filament и Jobs запрещён
- Значения по умолчанию и справочные данные живут в сидерах или конфигурации, а не в коде Blade и контроллеров

## HTML

- Сначала семантические теги: `<main>`, `<section>`, `<article>`, `<nav>`
- Доступность обязательна: `alt` на каждом изображении (фото товаров тоже), `aria-*` и `role` где нужно
- Никаких inline-стилей — только классы

## CSS

- Mobile-first (так же устроены брейкпоинты Tailwind)
- Стили — утилитами Tailwind прямо в Blade. Повторяющийся блок (2+ раза) выносится в Blade-компонент, а не в копию набора классов
- Собственный CSS — только в `resources/css/` и только для того, что утилитами не выражается. Методология BEM не используется
- Значения (цвета, отступы, шрифты) берутся из темы Tailwind. Произвольные значения вида `w-[137px]` — исключение, а не норма
- Весь CSS, JS и шрифты — свои, собранные Vite и отдаваемые с нашего сервера. Никаких CDN: сайт не должен зависеть от чужой доступности
- `!important` не использовать
- Оформление Filament менять средствами темы Filament, а не CSS поверх него (проверить в документации Filament 5)

## JavaScript

- ES Modules, async/await, стрелочные функции
- Функциональный стиль — без классовых компонентов
- Для небольшой интерактивности (меню, переключатели, раскрытие блоков) — Alpine.js из комплекта Livewire. Сложное состояние — Livewire-компонент
- Никакого jQuery и глобальных переменных
