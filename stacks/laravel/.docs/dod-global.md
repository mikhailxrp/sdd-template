# Global Definition of Done

Эти критерии применяются к каждому таску.
Проверяй вручную перед тем как считать задачу выполненной.

**Всегда критичны разделы «Данные» и «Безопасность»:** непройденный пункт из них = таск не принят, без исключений. Остальные разделы проверяются по затронутому скоупу: если таск не касается пункта, он отмечается как неприменимый, а не пропускается молча.

Блоки включённых пакетов (платежи, заявки, обмен с 1С и т.д.) лежат в конце файла, в разделе «Блоки пакетов». Если пакет не включён, его блока здесь нет. Блок с пометкой «Критично» приравнивается к разделам «Данные» и «Безопасность»: непройденный пункт = таск не принят.

## UI

- [ ] Страница открывается без ошибок
- [ ] Нет сломанной вёрстки
- [ ] Страница корректно отображается на мобильном (320px+)
- [ ] Если таск затрагивает админку: страницы ресурса Filament открываются, создание, редактирование и удаление записи работают, фильтры и сортировка таблицы не ломаются

## Данные

- [ ] После отправки формы — запись появляется в БД
- [ ] Выводится уведомление об успехе или ошибке
- [ ] Данные других пользователей недоступны: доступ ограничен Policy (CORE-4), а не только скрытием в интерфейсе
- [ ] Пользователь не может увидеть или изменить чужую запись (заявку, кабинет и т.п.), подставив чужой id в URL или в параметр Livewire-компонента
- [ ] Операции, меняющие несколько таблиц, либо проходят целиком, либо откатываются: внутри `DB::transaction()` в Action, не бывает наполовину применённых
- [ ] Если таск меняет счётчики или остатки: изменение защищено от гонки при параллельных запросах — условный `UPDATE … WHERE …` или `lockForUpdate()` в транзакции, а не «прочитать, потом записать» (голая транзакция от гонки не защищает)
- [ ] Job идемпотентен: повторный запуск (`php artisan queue:retry`) не дублирует результат — письма, записи, внешние вызовы
- [ ] Миграция применяется на чистой БД (`php artisan migrate:fresh --seed` локально) и не требует правки уже применённых миграций (CORE-8)

## Безопасность

- [ ] Незалогиненный пользователь не может открыть защищённую страницу (middleware `auth`)
- [ ] Если страница или действие только для администратора, проверяется Policy или `canAccessPanel()`, а не только факт логина: обычный пользователь, зная URL, получает 403 (CORE-4)
- [ ] Вывод данных в Blade только через `{{ }}`; `{!! !!}` не применяется к данным пользователя (CORE-9)
- [ ] Формы с POST содержат `@csrf` (Livewire защищает свои запросы сам). Список исключений CSRF в `bootstrap/app.php` пуст или содержит только вебхуки, описанные в блоке пакета и защищённые проверкой подписи (CORE-13)
- [ ] Вход и публичные формы ограничены по частоте попыток через `throttle` (CORE-13). Проверить вручную серией быстрых повторных запросов: ожидается `429`
- [ ] Если таск загружает файлы: тип проверен на сервере по содержимому файла (правила `mimes`/`mimetypes`), а не по имени; размер ограничен (`max`); файл сохранён через `Storage` под сгенерированным именем (CORE-12). Проверка: файл `.php` с расширением `.jpg` отклоняется
- [ ] Файлы из `storage` не выполняются как PHP: nginx запускает PHP только для `public/index.php` (проверить `curl` загруженного файла с продакшен-конфигом)
- [ ] Вход и восстановление пароля не показывают, что именно неверно: «неверный email или пароль», а не «такого пользователя не существует» (иначе перебором узнают, кто зарегистрирован)
- [ ] Авторизация реализована штатными средствами Laravel и Filament; самописной проверки пароля и сессий нет (id сессии при входе обновляется штатно)
- [ ] Cookies сессии и заголовки безопасности не переопределены вручную в контроллерах, они настроены централизованно: `config/session.php` и middleware `SecurityHeaders` (проверить поиском: `header(` и `config(['session` вне этих мест не встречаются)
- [ ] Публичная форма (заявка, обратный звонок, отзыв — любая, куда пишет незалогиненный посетитель) защищена от ботов тремя независимыми уровнями, если этого требует `NFR-SEC-*` проекта (ТЗ, раздел 11.4 «Безопасность»; конкретный ID — в `planning-log.md` / `.docs/modules/`). Если в проекте `NFR-SEC-*` явно фиксирует «защита от спама не реализуется», этот пункт DoD снят, и это тоже должно быть записано, а не просто отсутствовать:
      1. Honeypot-поле: скрыто от человека CSS (`display:none` в разметке, не просто атрибут `hidden`, который некоторые боты пропускают), заполнение отклоняет отправку молча
      2. Минимальное время заполнения: метка времени ставится при показе формы, сверяется при отправке, отправка быстрее 2–3 секунд отклоняется молча
      3. Одноразовый токен формы: отдельный от CSRF-токена, привязан к конкретному показу формы, не переиспользуется

      Реализация (свой middleware или пакет) фиксируется решением в `.docs/dev-log.md`. При срабатывании любого уровня пользователю показывается обычное «Спасибо, заявка принята» без пометки об ошибке; запись в БД, письмо и уведомление не создаются, попытка логируется. Отказ бота ничем не должен отличаться от успеха с точки зрения ответа сервера, иначе автора бота это наведёт на попытки обхода
- [ ] Путь к файлу (скачивание, картинка) не собирается напрямую из пользовательского ввода: файлы выдаются через `Storage` по идентификатору записи из БД, а не по пути из запроса; `../` в параметре не даёт выйти за пределы разрешённой папки (Path Traversal)
- [ ] Редирект после действия (вход, смена языка) не берёт адрес напрямую из запроса: используются именованные маршруты (`route()`) и `redirect()->intended()`. Если адрес из параметра нужен, он сверяется со списком своих URL, иначе `?redirect=` превращается в фишинговый редирект с доверенного домена (Open Redirect)
- [ ] В модель передаются только проверенные данные: `$request->validated()`, у модели явный `$fillable` без служебных полей (`role`, `is_admin`, `price`) (CORE-3, CORE-5, Mass Assignment)
- [ ] Livewire: идентификаторы в публичных свойствах защищены `#[Locked]`; каждый метод-обработчик, меняющий данные, валидирует ввод и проверяет права (`laravel.md`)
- [ ] Служебные файлы недоступны по прямому URL: `.git/`, `.env`, `composer.json`, `composer.lock`, `vendor/`, `storage/` (кроме `storage:link`), бэкапы БД. Проверить `curl` этих путей с продакшен-конфигом веб-сервера, не полагаться на то, что «их же никто не найдёт»; document root — только `public/`
- [ ] На проде `APP_DEBUG=false`, пользователь не видит стектрейс, путь к файлу или текст SQL-запроса; у него страница с человекочитаемым сообщением, подробности только в `storage/logs/` (CORE-6)
- [ ] Ответ сервера отдаёт заголовки `X-Content-Type-Options: nosniff`, `Referrer-Policy` и защиту от встраивания во фрейм (`X-Frame-Options` или `frame-ancestors`); `Strict-Transport-Security` настроен в nginx. Проверить `curl -I` на реальный URL проекта. Если введён `Content-Security-Policy`, страницы с Livewire и админка Filament проверены в браузере: консоль без ошибок CSP
- [ ] `composer audit` не показывает известных уязвимостей в зависимостях (или найденные записаны в `.docs/dev-log.md` с решением)

## Производительность

- [ ] Новый запрос с фильтром, поиском или сортировкой — под него есть индекс в `.docs/database.md` и в миграции. Индекс на каждый внешний ключ создан явно (PostgreSQL не создаёт его сам)
- [ ] Списки выводятся через пагинацию, а не одним запросом без `LIMIT`; на глубоких страницах — `cursorPaginate()`
- [ ] Нет N+1: при открытии страницы в окружении с `Model::shouldBeStrict()` не возникает `LazyLoadingViolationException`; связи подгружены через `with()`

## SEO и GEO

- [ ] У каждой публичной страницы — свой `<title>` и `<meta name="description">`, оба непустые и не задублированы с другой страницей. Значение берётся из `seo_title` / `seo_description` сущности (`.docs/database.md`); если поле пусто — подставляется запасной вариант в `<x-seo>`, а не хардкод во view конкретной страницы
- [ ] На странице ровно один `<h1>`; `<h2>`/`<h3>` идут по смысловой вложенности контента, не выбраны из-за размера шрифта
- [ ] У каждого `<img>` есть непустой `alt`, описывающий содержимое (не имя файла и не пустая строка); декоративные картинки имеют явный `alt=""`
- [ ] Контент страницы присутствует в HTML-ответе сервера и виден без выполнения JS (`curl` страницы или «просмотр кода страницы», а не только то, что видно после рендеринга); контент, важный для SEO, не загружается через `lazy` и `wire:init`. Большинство ИИ-краулеров (в отличие от Google) не исполняют JS вообще
- [ ] Если для типа страницы в блоке пакета задана разметка schema.org, она валидируется через Google Rich Results Test или аналог, а не «на глаз»; значения в разметке совпадают с видимым текстом страницы
- [ ] У страниц с параметрами фильтра, сортировки или пагинации есть `<link rel="canonical">` на базовый URL: иначе каждая комбинация фильтров индексируется как отдельная страница-дубль
- [ ] `/sitemap.xml` отвечает `200`, не пустой, содержит реальные URL опубликованных сущностей и не содержит скрытых и неопубликованных
- [ ] `public/robots.txt` существует, закрывает `/admin/` и пути из блоков пакетов, содержит строку `Sitemap:` и не блокирует то, что должно индексироваться (например, случайно закрыт `/catalog/` или `/build/`)
- [ ] URL страницы человекочитаем и стабилен (`/catalog/divany`, не `/product?id=482`); если таск создаёт новый тип страницы, она получает URL по `slug`, а не числовому id
- [ ] Вне production ответы отдают `X-Robots-Tag: noindex` (проверить `curl -I` на тестовом стенде)

## Формы и валидация

- [ ] Пустая форма не отправляется — поля подсвечиваются
- [ ] Некорректные данные — поля подсвечиваются с ошибкой; ошибки приходят от Form Request или `rules()` компонента, а не из самодельных проверок в шаблоне
- [ ] После ошибки валидации введённые данные сохраняются (`old()` или состояние Livewire), пользователю не нужно вводить всё заново

## Код

- [ ] Нет ошибок в консоли браузера
- [ ] Нет ошибок и warnings в `storage/logs/` после прохождения сценария таска
- [ ] `vendor/bin/pint --test` проходит без замечаний
- [ ] `vendor/bin/pest` проходит полностью
- [ ] Нет сырого SQL в контроллерах, Livewire-компонентах и Blade. `DB::raw`, `DB::select`, `DB::statement` встречаются только в миграциях и местах, разрешённых блоком пакета (CORE-2)
- [ ] Бизнес-логика лежит в `app/Actions`, а не в контроллерах, Livewire-компонентах, Filament-ресурсах, моделях (CORE-1, CORE-14)
- [ ] `env()` встречается только в `config/*.php` (проверить поиском по `app/`, `routes/`, `resources/`)
- [ ] Нет неиспользуемых переменных и импортов, которые появились из-за этого таска (предсуществующий мёртвый код рядом не в скоупе; если заметил, просто упомяни)
- [ ] Деньги нигде не хранятся и не считаются как `float`
- [ ] Новые файлы начинаются с `declare(strict_types=1)`, сигнатуры типизированы (CORE-15)
- [ ] Если таск добавляет или меняет Action, для неё есть тест Pest (CORE-16). Критичные потоки покрыты Feature-тестом; автотесты дополняют ручную проверку, а не заменяют её для вёрстки и админки
- [ ] Новый Composer/NPM-пакет добавлен только вместе с записью решения в `.docs/dev-log.md`
