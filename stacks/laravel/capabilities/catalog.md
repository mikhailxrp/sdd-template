# Каталог товаров

Публичный каталог: дерево категорий, карточки товаров, фото, характеристики, поиск по артикулу и тексту, фильтры. Админка каталога — в Filament. Корзины, заявок и цен по клиентам здесь нет: это отдельные пакеты.

## Параметры

| Параметр | Зачем | Пример |
|----------|-------|--------|
| Число товаров и категорий | Влияет на индексы, кэш и пагинацию | 1 000–10 000 товаров, до 300 категорий |
| Показ цены | Определяет поведение `<x-price>`, схемы `offers` и фильтров по цене | всем / только авторизованным / «по запросу» |
| Единицы измерения | Колонка `unit`, формат вывода остатка | шт, л, кг; дробные количества нужны или нет |
| Показ остатка | Числом или статусом, пороги статусов | «в наличии» / «мало» / «под заказ» |
| Характеристики для фильтров | Какие записи справочника получают `is_filterable` | бренд, вязкость, объём, допуски |
| Страницы брендов | Если нужны, бренд оформляется отдельной сущностью (в «Дополнительные таблицы» проекта) | да / нет |
| Несколько категорий у товара | По умолчанию одна категория; если нужно несколько, добавляется связь в проекте | да / нет |
| Источник фото | Загрузка вручную, из учётной системы, внешние ссылки | вручную в Filament |
| Валюта | Для `priceCurrency` в разметке | RUB |

## Правила

1. **CAT-1.** Запись в таблицы каталога (`categories`, `products`, `product_images`, `product_attributes`, `product_attribute_values`) выполняется только через Actions в `app/Actions/Catalog/`. Админка, импорт и любые фоновые процессы пишут одним путём, второго пути нет.
2. **CAT-2.** Публичная выборка товаров и категорий идёт только через scope `published()` (опубликованная сущность и опубликованная категория). Прямой `Product::query()` в публичном коде запрещён. Неопубликованная или несуществующая сущность по прямому URL отдаёт 404, а не пустую страницу.
3. **CAT-3.** Товар физически не удаляется: скрывается `is_published = false`. Категорию, в которой есть товары или подкатегории, удалить нельзя (`RESTRICT`).
4. **CAT-4.** Адреса: категория — `/catalog/{category-slug}`, товар — `/product/{product-slug}` (допущение — подтвердить). Товар не привязан к пути категории, поэтому перенос между категориями не ломает URL. Привязка по `slug` (route model binding). При коллизии `slug` товара к нему добавляется артикул.
5. **CAT-5.** `sku` хранится как в источнике, без правок. Для поиска используется `sku_normalized`: нижний регистр, без пробелов, дефисов и точек (допущение — подтвердить). Поиск по артикулу идёт только по `sku_normalized`: точное совпадение и по префиксу.
6. **CAT-6.** Текстовый поиск — только через scope `Product::search()` с полнотекстовым индексом (`search_vector`, конфигурация `russian`). `ILIKE '%…%'` запрещён. Сырой SQL допустим только в этом scope (см. «Исключения из правил ядра»).
7. **CAT-7.** Сортировка и фильтры принимают только значения из списка разрешённых (whitelist в коде). Имя колонки из запроса напрямую в `orderBy` или `where` не подставляется никогда. Для всех параметров заданы значения по умолчанию.
8. **CAT-8.** Характеристики хранятся только через справочник `product_attributes` и значения `product_attribute_values`. В `description` характеристики не вшиваются. Числовой атрибут записывает значение и в `value`, и в `value_number`.
9. **CAT-9.** Цена выводится только через один Blade-компонент `<x-price>`, который учитывает режим показа из `prd.md`. Прямой вывод `$product->price` в Blade запрещён. `price = NULL` означает «по запросу»: ноль и пустая строка цены не показываются. Значение в разметке и на странице берётся из одной переменной.
10. **CAT-10.** `stock_quantity = NULL` означает «остаток неизвестен» и не показывается как «нет в наличии». Формат показа (число или статус) и пороги задаются в `prd.md`.
11. **CAT-11.** У товара не больше одного главного изображения: частичный уникальный индекс на `product_images`. Если `alt` пуст, подставляется название товара.
12. **CAT-12.** Списки каталога — только с пагинацией (размер страницы в `config/`, по умолчанию 24); на глубоких страницах `cursorPaginate()`. Счётчики фасетов считаются одним сгруппированным запросом и кэшируются на короткий срок; запрос на каждое значение фильтра запрещён.
13. **CAT-13.** Дерево категорий читается целиком одним запросом (или рекурсивным CTE) и собирается в памяти. Запрос на каждый уровень вложенности запрещён. Результат кэшируется, кэш сбрасывается из Action, изменившей категории.

### Исключения из правил ядра

- `CORE-2`: сырой SQL (`whereRaw`, `selectRaw`, `orderByRaw`) допустим только внутри `Product::scopeSearch()` для полнотекстового поиска (`websearch_to_tsquery`, `ts_rank`), строго с биндингами. Генерируемая колонка и специальные индексы создаются в миграциях, где сырой SQL разрешён и так.

## Каталоги

```
app/Actions/Catalog/            → операции: CreateProduct, UpdateProduct, PublishProduct, SetMainImage, …
app/Http/Controllers/Catalog/   → страницы категории и товара
app/Livewire/Catalog/           → листинг с фильтрами, сортировкой и поиском
app/Models/                     → Category, Product, ProductImage, ProductAttribute, ProductAttributeValue
app/View/Components/Price.php   → компонент цены <x-price>
app/Filament/Resources/         → CategoryResource, ProductResource, ProductAttributeResource
```

Имя модели справочника — `ProductAttribute`, а не `Attribute`: последнее занято классом Eloquent для аксессоров.

### `products`

| Колонка | Тип | Назначение |
|---------|-----|------------|
| id | `id()` bigint PK | |

| sku | `string(64)` NOT NULL UNIQUE | артикул как в источнике |

| description | `text()` NULL | |
| unit | `string(16)` NOT NULL DEFAULT 'шт' | единица измерения |
| price | денежный тип проекта (`decimal(12,2)` по умолчанию, см. соглашения `database.md`) NULL | NULL = «по запросу» |

| seo_description | `string(160)` NULL | |
| search_vector | `tsvector`, генерируемая колонка `GENERATED ALWAYS AS (to_tsvector('russian', …)) STORED` | по названию, артикулу и описанию; создаётся в миграции через `DB::statement` (проверить в документации PostgreSQL) |
| created_at, updated_at | `timestamps()` | |

**Индексы:**
- `INDEX(category_id, is_published)` — листинг по категории
- `INDEX(price)` — сортировка и фильтр по цене
- `INDEX(sku_normalized varchar_pattern_ops)` — поиск артикула по префиксу
- `GIN(search_vector)` — текстовый поиск

### `product_attributes`

Справочник характеристик: исключает разнобой вида «5W30» и «5W-30» в названиях.

| Колонка | Тип | Назначение |
|---------|-----|------------|
| id | `id()` bigint PK | |
| name | `string(100)` NOT NULL | «Вязкость», «Объём» |
| slug | `string(120)` NOT NULL UNIQUE | для параметров фильтра в URL |
| type | `string(16)` NOT NULL | enum `string` или `number` |
| unit | `string(16)` NULL | «л», «мм» |
| is_filterable | `boolean()` NOT NULL DEFAULT false | выводится ли в фильтрах |
| sort_order | `integer()` NOT NULL DEFAULT 0 | |

### `product_attribute_values`

| Колонка | Тип | Назначение |
|---------|-----|------------|
| id | `id()` bigint PK | |
| product_id | `foreignId()`, FK → products.id, `cascadeOnDelete` | |
| product_attribute_id | `foreignId()`, FK → product_attributes.id, `restrictOnDelete` | используемую характеристику удалить нельзя |
| value | `string(255)` NOT NULL | значение для показа и фильтра |
| value_number | `decimal(14,4)` NULL | числовое значение для диапазонов и сортировки |

**Индексы:**
- `UNIQUE(product_id, product_attribute_id, value)` — допускает несколько значений одной характеристики (например, несколько допусков); начинается с `product_id`, поэтому обслуживает и внешний ключ
- `INDEX(product_attribute_id, value)` — фильтр по значению
- `INDEX(product_attribute_id, value_number)` — диапазоны

**Связи:**

```
categories (1)
  ├──< categories (self, parent_id, RESTRICT)
  └──< products (1:N, RESTRICT)

products (1)
  ├──< product_images (1:N, CASCADE)
  └──< product_attribute_values (1:N, CASCADE)

product_attributes (1)
  └──< product_attribute_values (1:N, RESTRICT)
```

## SEO

| Страница | schema.org | Обязательные поля | robots / sitemap |
|----------|------------|-------------------|------------------|
| Категория `/catalog/{slug}` | `BreadcrumbList` | цепочка родителей, та же, что в видимых «хлебных крошках» | в sitemap: опубликованные категории; URL с фильтрами и сортировкой в sitemap не входят |
| Товар `/product/{slug}` | `Product` + `BreadcrumbList` | `name`, `sku`, `image` (если есть); `offers.price`, `offers.priceCurrency`, `offers.availability` только если цена показывается | в sitemap: опубликованные товары опубликованных категорий |
| Результаты поиска | — | — | `Disallow: /search` (внутренний поиск не индексируется) |

Если цена не показывается (по запросу или только авторизованным), блок `offers` не выводится вовсе, а не выводится с нулём. `availability` и цена в разметке берутся из тех же переменных, что и видимый текст.

## DoD

- [ ] Страница товара открывается по `slug`; скрытый товар и товар скрытой категории отдают 404 и не попадают в sitemap
- [ ] Категорию с товарами удалить нельзя (проверить в админке), товар удаляется только скрытием
- [ ] Поиск находит товар по артикулу целиком, по префиксу и по варианту написания без дефисов, а также по названию
- [ ] Фильтры по характеристикам работают, состояние фильтра отражается в URL, canonical ведёт на чистый URL категории
- [ ] Сортировка принимает только разрешённые значения: `?sort=price;drop` или неизвестное поле не ломают страницу и не меняют запрос
- [ ] У каждого товара не более одного главного фото (повторная попытка отклоняется БД)
- [ ] Цена выводится только через `<x-price>`; в режиме «по запросу» цены нет ни на странице, ни в разметке
- [ ] Остаток `NULL` показывается как «уточняйте», а не «нет в наличии»
- [ ] Разметка `Product` проходит Google Rich Results Test; цена и наличие в ней совпадают с видимыми
- [ ] Листинг на странице глубже сотой не замедляется заметно (`cursorPaginate()`), список использует `with()` для главного фото
- [ ] Операции записи в каталог идут через Actions, прямых `Product::create/update` вне Actions нет
- [ ] При изменении категории меню и дерево обновляются (кэш сброшен)

## Проверки аудита

- Функциональные: поиск по артикулу (точно, префикс, нормализованный), по названию; 404 для скрытого; переход между категориями не ломает URL товара
- Безопасность: параметры `sort`, `filter`, `page`, `q` не подставляются в SQL напрямую; публичный код не обходит `published()`; изменение `price`, `is_published`, `stock_quantity` недоступно с публичной стороны
- Производительность: N+1 в листинге (главное фото, категория), план запроса листинга и поиска использует индексы

## Фазы

- **Первый вертикальный срез (что показать клиенту):** миграции каталога, тестовые данные на 30–50 товаров, листинг и карточка товара, SEO-теги и хлебные крошки, редактирование в Filament. Это уже можно открыть в браузере
- **Затем:** поиск (артикул + текст), справочник характеристик и фильтры. Самая рискованная часть здесь — качество поиска на реальных данных: тесты поиска пишутся внутри этой фазы
- **Параллельно после миграций:** админка Filament и публичные страницы
- Если включены другие пакеты, они опираются на Actions этого пакета, поэтому Actions пишутся в первом срезе, а не позже

## С другими пакетами

- Если включён `onec-sync`: поля, которыми владеет учётная система (артикул, название, цена, остаток, единица, привязка к категории), в Filament доступны только для чтения; изменения идут через обмен. На сайте остаются описание, SEO-поля, фото и slug (уточняется в пакете `onec-sync`)
- Если включён `ai`: при изменении названия, описания или характеристик пересчитывается смысловой вектор товара (Job, CORE-7)
- Если включён `leads`: карточка товара может передавать `product_id` в форму заявки; в заявку копируются название и артикул как снимок на момент отправки
- Если включён `cart-checkout`: товар, на который есть позиции заказов, не удаляется ни при каких условиях, только скрывается (CAT-3)
