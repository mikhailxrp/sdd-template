# Онлайн-оплата

Заготовка пакета (`status: stub`). Перед включением в проект необходимо заполнить пакет по `_format.md` строго после выбора платёжного провайдера и сверки с его официальной документацией. Формулы подписей, эндпоинты и статусы провайдера не придумывать.

## Что нужно выяснить перед написанием

- **Платёжный провайдер:** ЮKassa, Т-Банк, Сбер, Robokassa или иной; актуальная версия API и официальная документация `(проверить в документации провайдера)`
- **Сценарий оплаты:** одностадийная (списание сразу) или двухстадийная (холдирование → подтверждение); поддерживаемые методы (карты, СБП, оплата по счёту)
- **Вебхуки и безопасность:** точный механизм проверки подлинности уведомлений (подпись HMAC/SHA, список IP провайдера, дополнительный запрос статуса по API), исключение CSRF только для маршрута вебхука с обязательной проверкой подписи (`CORE-13`), идемпотентность обработки повторных вебхуков
- **Фискализация (54-ФЗ):** кто формирует чеки (касса провайдера, АТОЛ Онлайн, CloudKassir, 1С), ставки НДС, признак способа и предмета расчёта, передача позиций заказа и доставки в чек `(проверить в документации кассы/провайдера)`
- **Возвраты и отмены:** полные и частичные возвраты из Filament (Policy + Action), формирование чека возврата, идемпотентность запроса возврата (`Idempotence-Key`)
- **Таймауты и расхождения:** время жизни платёжной ссылки, сверка зависших платежей по расписанию (polling статуса при потерянном вебхуке), снятие резерва при истечении срока оплаты
- **Журнал платежей (`payment_logs`):** какие поля хранятся для аудита без сохранения данных банковских карт (PCI DSS) и секретных ключей
