## Tech Stack

**Используем:**

| Слой          | Технология                                   | Почему                                                              |
| ------------- | -------------------------------------------- | ------------------------------------------------------------------- |
| Backend       | Laravel 13 (PHP 8.3+)                        | Очереди, планировщик, авторизация, валидация из коробки             |
| БД            | PostgreSQL                                   | Одна БД для данных и (если включён пакет `ai`) для векторного поиска |
| Frontend      | Blade + Livewire 4 (Alpine.js из комплекта)  | SSR для SEO, интерактив без отдельного SPA                          |
| Стили/сборка  | Tailwind CSS + Vite                          | Общий стек с Filament и Livewire                                    |
| Админка       | Filament 5                                   | Админка без самописного UI                                          |
| Авторизация   | Laravel Auth (сессии) + Policies             | Встроено                                                            |
| Очереди       | Laravel Queue (драйвер задаётся в prd.md)    | Долгие и внешние операции вне запроса                               |
| Тесты         | Pest 4                                       | Короткий синтаксис, удобно агенту                                   |
| Code style    | Laravel Pint                                 | Единый стиль без обсуждений                                         |

Версии зафиксированы в `composer.lock` / `package-lock.json`. Мажорные обновления — отдельной фазой, не попутно. (версии проверить на laravel.com / filamentphp.com при старте проекта)

**Окружение (допущение — подтвердить):** PHP 8.3+ (PHP-FPM), PostgreSQL, веб-сервер nginx. Node.js нужен только для сборки ассетов (локально/CI), на проде не нужен.

**Не используем — никогда:**

- Второй ORM или query-слой поверх Eloquent (Doctrine, паттерн Repository)
- Другие админ-пакеты рядом с Filament (Nova, Voyager, Backpack)
- React / Vue / Inertia — только если `.docs/prd.md` явно требует SPA-интерфейс
- jQuery
- Новые Composer/NPM-пакеты без записи решения в `.docs/dev-log.md`

## Ключевые правила проекта

Нумерация `CORE-N` — правила ядра. Правила пакетов имеют свои префиксы (см. «Правила пакетов»). При конфликте с кодом побеждает правило.

1. **CORE-1.** Бизнес-логика живёт только в `app/Actions/*`: один класс — одна операция, публичный метод `handle()`. Контроллеры, Livewire-компоненты, Filament-ресурсы, Jobs и консольные команды только вызывают Actions.
2. **CORE-2.** Доступ к данным — только через Eloquent (модели, scopes, query builder). Сырой SQL запрещён вне миграций. Исключение — только то, что описано в правилах включённого пакета, и только с биндингами, никогда конкатенацией.
3. **CORE-3.** Входные данные валидируются только через Form Request (HTTP) или `rules()` Livewire-компонента / Filament-формы. Использовать `validated()`; `$request->all()` запрещён.
4. **CORE-4.** Права доступа проверяются только через Policies/Gates. Проверка роли руками (`if ($user->role === …)`) в контроллерах, Livewire и Blade запрещена.
5. **CORE-5.** У каждой модели явный `$fillable`. `$guarded = []` и `Model::unguard()` запрещены.
6. **CORE-6.** `env()` вызывается только в `config/*.php`, в остальном коде — `config('…')`. `.env` в `.gitignore`, в репозитории только `.env.example`.
7. **CORE-7.** Обращение к внешним сервисам, отправка писем и уведомлений, импорт/экспорт и генерация файлов выполняются только в Jobs через очередь. Job идемпотентен: повторный запуск не дублирует результат.
8. **CORE-8.** Схема БД меняется только миграцией (`php artisan make:migration`). Применённую миграцию не править — новое изменение = новая миграция. Ручной DDL на проде запрещён.
9. **CORE-9.** Вывод в Blade — только через `{{ }}`. `{!! !!}` допустим только для HTML, прошедшего санитайзер, с комментарием, зачем.
10. **CORE-10.** N+1 запрещены: связи подгружаются через `with()`. В не-prod окружении включено `Model::preventLazyLoading()`.
11. **CORE-11.** В БД время хранится в UTC; пояс отображения берётся из конфигурации проекта (`.docs/prd.md`) (допущение — подтвердить). Во всех таблицах есть первичный ключ и `timestamps`.
12. **CORE-12.** Файлы пользователей сохраняются только через `Storage` с проверкой типа и размера. Исполняемые файлы не принимаются. Публичный доступ — только через `storage:link` или подписанные URL.
13. **CORE-13.** Публичные формы и auth-эндпоинты всегда за `throttle`. CSRF не отключается; исключения (вебхуки) описываются в правилах пакета и проверяются подписью.
14. **CORE-14.** Filament-ресурсы не содержат бизнес-логики: операции вызывают Actions. Доступ в панель — через `canAccessPanel()` + Policies.
15. **CORE-15.** Новые файлы — с `declare(strict_types=1)` и типизированными сигнатурами. Перед завершением задачи `vendor/bin/pint` и `vendor/bin/pest` проходят без ошибок.
16. **CORE-16.** Каждая Action покрыта тестом (Pest). Критичные потоки (авторизация, заявки, всё, что меняет деньги или данные клиента) — Feature-тестом.

## Архитектура

```
app/Actions/            → бизнес-логика: одна операция = один класс, handle()
app/Http/Controllers/   → тонкие контроллеры публичной части: request → Action → view/redirect
app/Http/Requests/      → Form Requests: валидация и авторизация входа
app/Livewire/           → интерактивные компоненты публичной части (фильтры, формы, чат)
app/Models/             → Eloquent: связи, scopes, casts, $fillable; без бизнес-логики
app/Policies/           → права доступа по моделям
app/Jobs/               → очередь: внешние вызовы, импорт, рассылки (идемпотентные)
app/Services/           → обёртки над внешними системами (HTTP-клиенты, почта); без бизнес-логики
app/Enums/              → статусы и типы (backed enums)
app/Filament/           → админка: Resources, Pages, Widgets (только UI + вызов Actions)
app/Providers/Filament/ → конфигурация панели Filament
bootstrap/app.php       → роутинг, middleware, обработка исключений
routes/web.php          → публичные маршруты
routes/console.php      → расписание (Scheduler)
routes/api.php          → только если пакет требует входящий API/вебхуки (opt-in)
config/                 → конфигурация; единственное место для env()
database/migrations/    → схема БД, только вперёд
database/factories/     → фабрики для тестов
database/seeders/       → начальные данные (роли, справочники)
resources/views/        → Blade-шаблоны
resources/views/components/ → переиспользуемые Blade-компоненты
resources/css, resources/js → ассеты, собираются Vite
tests/Feature/          → Pest: потоки и HTTP
tests/Unit/             → Pest: чистая логика Actions
storage/logs/           → логи приложения (вне document root)
public/                 → document root, единственная точка входа
.env                    → секреты, в .gitignore
```

Каждый включённый пакет может добавить свои каталоги (например, `app/Actions/Catalog/`). Они описаны в его блоке «Правила».

## Правила по слоям

| Слой                | Отвечает за                                   | Не делает                                     |
| ------------------- | --------------------------------------------- | --------------------------------------------- |
| Controller          | Принять запрос, вызвать Action, вернуть ответ | Бизнес-логика, SQL, валидация внутри метода   |
| Livewire-компонент  | Состояние UI, вызов Actions                   | Бизнес-логика, прямые запросы с цепочками     |
| Action              | Одна бизнес-операция                          | HTML, редиректы, чтение `Request`             |
| Model               | Связи, scopes, casts, `$fillable`             | Бизнес-логика, HTTP, письма                   |
| Service             | Вызовы внешних систем                         | Бизнес-решения (что и когда вызывать — Action) |
| Job                 | Выполнить Action в очереди                    | Своя бизнес-логика                            |
| Blade               | Вывод данных                                  | SQL, бизнес-логика                            |
| Filament Resource   | UI админки                                    | Бизнес-логика (вызывает Actions)              |

POST-запрос публичной части заканчивается redirect (Post/Redirect/Get). Livewire-компонент после успешной отправки показывает состояние результата.

### CSS / JS / HTML

- Tailwind: утилиты в Blade, повтор 2+ раз = выноси в Blade-компонент в `resources/views/components/`
- Никаких inline-стилей (`style="…"`)
- JS: ES Modules, async/await; для небольшой интерактивности — Alpine.js; никаких глобальных переменных и jQuery
- Семантические теги: `<main>`, `<section>`, `<article>`, `<nav>`
- `alt` на всех изображениях, `aria-*` где нужно
- Mobile-first

## Безопасность

Базовые правила — `CORE-3`, `CORE-4`, `CORE-5`, `CORE-6`, `CORE-9`, `CORE-12`, `CORE-13`. Детали и примеры — `.docs/rules/laravel.md`. Расширения для платежей, вебхуков и интеграций — в блоках включённых пакетов.

- Пароли — только встроенный `Hash` Laravel, никогда md5/sha1
- `APP_DEBUG=false` и `APP_ENV=production` на проде
- Секреты (ключи API, токены) — только в `.env`, никогда в коде, логах и `dev-log.md`

## AI Rules (для агента)

- Перед задачей читать `TASK.md` и `phase-N.md`
- Работать только в scope текущего таска
- Не менять файлы вне scope
- Не рефакторить попутно
- Перечислять файлы, которые будут изменены
- Сначала анализ → план → список файлов → только потом код
- Для многошаговых тасков — на каждый шаг сразу указывать, чем он будет проверен (тест Pest, ручная проверка в браузере, конкретный пункт DoD), а не только что сделать
- Файлы создавать через `php artisan make:*`, а не вручную, когда команда существует
- `vendor/`, `composer.lock` и `package-lock.json` руками не править
- Не подгонять `.docs/prd.md` под написанный код: расхождение кода и требования — дефект реализации

### Стиль ответов

- Общение — на русском. Код, идентификаторы, имена файлов, коммиты — на английском
- Перед кодом — короткий план

### Поддержка документации проекта

- Изменения и решения фиксируй в `.docs/dev-log.md` — не версионируй `AGENTS.md` записями вида «v1.2 — добавлено…» внутри самого файла. `AGENTS.md` описывает текущее состояние, а не историю изменений
- Если правило уже описано в файле (`AGENTS.md`, `laravel.md`, `database.md`) — обновляй его на месте. Не добавляй второе упоминание того же факта в другом разделе или файле: две копии одного правила рано или поздно разойдутся
- WHY у неочевидного архитектурного решения — 1-2 строки прямо на месте (в дереве папок, в таблице). Если объяснение начинает разрастаться в абзац с историей — выноси в отдельный файл (`.docs/modules/<name>.md` или аналог), а на месте оставляй только короткую ссылку на него
- Состав пакетов и параметры проекта меняются только в `.docs/prd.md` → «Возможности», затем перегенерируются `AGENTS.md`, `database.md`, `dod-global.md`
