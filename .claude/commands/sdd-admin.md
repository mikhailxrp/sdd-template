Прочитай:
- `reference/sdd-planning-agent.md`
- `00-input/tz.md` — разделы 8.15 (MGR), 8.16 (ADM), все `FR-ADM-*`,
  `FR-MGR-*` в полном тексте (это единственный шаг, где их нужно читать
  целиком — здесь решается состав экранов, не только фаза)
- `00-input/tz.md` раздел 8 целиком (интеграции, CRM, учётные системы)
  и все `FR-CHANNELS-*` — нужны для двух специфичных экранов, см. шаг 6
- `.docs/tz-coverage.md` — что уже известно об этих требованиях
- `.docs/database.md` — из него берутся поля таблиц и форм
- `public/assets/vendor/tabler/VERSION.txt` — версия Tabler и иконок
- список папок в `public/assets/vendor/tabler/libs/` — это единственные
  доступные виджеты (графики, выбор даты, загрузка файлов и т.д.)

Если папки `public/assets/vendor/tabler/` нет — сообщи и остановись,
эта команда работает только если стартер стека включает Tabler.

**Эта команда пишет только план (`.docs/admin-assembly.md`) и обновляет
`tz-coverage.md`. Код экранов и копирование файлов — на этапе
`phase-init`/`task-init`, не здесь.** Готовых страниц админки в шаблоне
нет: Tabler — это набор компонентов (CSS, JS, виджеты, иконки), экраны
собираются из него под требования проекта.

## Что сделать

### 1. Определить экраны

Для каждого `FR-ADM-*`/`FR-MGR-*` реши:

| Ситуация | Действие |
|---|---|
| Требование покрывается экраном, который можно собрать из компонентов Tabler и виджетов из `libs/` | Включи экран в план |
| Нужного виджета в `libs/` нет (например, нужен компонент, которого в папке нет) | Не добавляй библиотеку и не подключай CDN — заведи `Q-DEV-NNN`, реши на этапе `phase-init`/`task-init` |
| Требование не удаётся перевести в экран по тексту ТЗ | Не выдумывай экран — заведи `Q-DEV-NNN` |

**Не включай экраны «на всякий случай».** Если требование явно не
затрагивает экран — он не нужен в этом проекте. Меньше кода — меньше
что поддерживать.

### 2. Подобрать компоненты для каждого экрана

Для каждого экрана укажи, из чего он собирается:
- базовые компоненты Tabler (карточка, таблица, форма, модальное окно,
  вкладки, бейдж статуса, пагинация, заголовок страницы, пустое состояние
  и т.п.)
- виджеты — только из `public/assets/vendor/tabler/libs/`
- иконки — только из `public/assets/vendor/tabler/icons/`

Правила:
- Не придумывай названия классов по памяти. Перед тем как записать класс
  в план, проверь, что он есть в
  `public/assets/vendor/tabler/css/tabler.min.css` (поиск по файлу), или
  сверься с документацией Tabler (tabler.io/docs).
- Все файлы подключаются локально, без CDN (правило `general.md`).
- Графики — по таблице стека в `CLAUDE.md` проекта; если там указана
  библиотека, которой нет в `libs/`, не решай молча — заведи `Q-DEV-NNN`.

### 3. Каркас админки

Первой строкой плана всегда идёт каркас, без него остальные экраны
собрать нельзя:
- общий layout админки (боковое меню, верхняя панель, область контента)
- подключение CSS, JS и иконок из `public/assets/vendor/tabler/`
- проверка роли `role = 'admin'` на каждом маршруте админки (правило из
  `dod-global.md`, не только факт логина)
- меню: только пункты на экраны из плана

### 4. Задокументировать план

Создай `.docs/admin-assembly.md`:

```markdown
# План экранов админки

Tabler <версия из VERSION.txt>. Экраны собираются из компонентов на этапе
разработки (`phase-init`/`task-init`), не сейчас. Эта команда только
фиксирует план, не пишет код.

| Экран | Покрывает | Компоненты Tabler | Виджеты (libs) | Поля (database.md) |
|---|---|---|---|---|
| Каркас админки | NFR/ADM-доступ | layout, меню, шапка | — | — |
| Список товаров | FR-ADM-001 | карточка, таблица, бейдж статуса, пагинация | — | фото, название, категория, цена, статус |
| Форма товара | FR-ADM-001 | карточка, форма | загрузка файлов, выбор из списка (категория) | поля таблицы products |
```

Строки выше — пример формата, не готовые решения: бери поля из
`database.md` **этого** проекта, виджеты — из реального содержимого
`libs/`, не общими словами.

Расположение файлов экранов — **архитектурный выбор, не общепринятая
практика**: предлагай `src/Views/admin/` (в стартере уже есть
`src/Views/layout/` и `src/Views/components/`), и отметь это в
`planning-log.md` как решение (ADR), если ещё не зафиксировано.

### 5. Обновить tz-coverage.md

Для каждого `FR-ADM-*`/`FR-MGR-*`: статус `Учтено`, с пометкой
`экран: <название из admin-assembly.md>`. Если требование ушло в
`Q-DEV-NNN` — статус `Не покрыто → Q-DEV-NNN`.

### 6. Экраны «Каналы продаж» и «Интеграции» — отдельные правила

Эти два экрана не привязаны к `FR-ADM-*`/`FR-MGR-*`, у них своя логика
включения — не добавляй в план по умолчанию вместе с остальными.

**«Каналы продаж»** — включай, только если в `tz.md` есть хотя бы одно
`FR-CHANNELS-*` (клиент в брифе 8.3 подтвердил, что нужен единый
инбокс). Если модуля `CHANNELS` в ТЗ нет вообще — не включай, не задавай
вопрос, это значит клиент отказался.

**«Интеграции»** — включай, если в разделе 8 ТЗ указана хотя бы одна CRM
или учётная система. Порядок:

1. Найди в разделе 8 ТЗ названия CRM (если есть) и учётных систем (1С,
   МойСклад и подобные, если есть) — это обычно строки таблицы
   интеграций и раздел 8.1 брифа
2. Если не найдено ничего (ни CRM, ни учётной системы) — не включай
   экран, заведи `Q-DEV-NNN` с пометкой «интеграции не указаны в ТЗ,
   уточнить у клиента при желании показать демо»
3. На экране — по одной строке на каждую названную систему, строки
   сгруппированы в блоки «CRM» и «Системы учёта»
4. Блок, по которому в ТЗ нет ни одной системы, на экран не включай
   (не оставляй пустой блок)
5. Название проекта и ответственного для шапки экрана — из раздела 1/12
   ТЗ

Не выдумывай названия систем, которых нет в ТЗ — только то, что клиент
явно назвал.

## Отчёт

- Сколько экранов в плане, список (включая каркас)
- Ссылка на `admin-assembly.md`
- Какие `FR-ADM-*`/`FR-MGR-*` не нашли соответствия — `Q-DEV-NNN`
- Какие виджеты из `libs/` задействованы
- «Каналы продаж»: включён или нет, почему
- «Интеграции»: включён или нет; если да — какие системы и в каких
  блоках, какие блоки не включены за отсутствием данных
