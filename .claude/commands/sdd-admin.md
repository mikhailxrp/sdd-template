Прочитай:
- `reference/sdd-planning-agent.md`
- `00-input/tz.md` — разделы 8.15 (MGR), 8.16 (ADM), все `FR-ADM-*`,
  `FR-MGR-*` в полном тексте (это единственный шаг, где их нужно читать
  целиком — здесь решается конкретная разметка, не только фаза)
- `.docs/tz-coverage.md` — что уже известно об этих требованиях
- `00-input/admin-template/admin-pages-manifest-classified.json` —
  список готовых страниц шаблона, что оставлено/удалено и почему
- `00-input/admin-template/admin-missing-pages.json` — страницы,
  которых в шаблоне нет, с указанием, из какого готового блока их
  собирать

Если папки `00-input/admin-template/` нет — сообщи и остановись,
эта команда работает только если стартер стека включает готовый
шаблон админки.

## Что сделать

### 1. Сопоставить требования со страницами

Для каждого `FR-ADM-*`/`FR-MGR-*` реши:

| Ситуация | Действие |
|---|---|
| Требование покрывается готовой страницей из манифеста | Пометь страницу к копированию |
| Требование покрывается страницей из `admin-missing-pages.json` | Пометь как «требует сборки», с указанием `build_from` |
| Требование не покрывается ни тем, ни другим | Не выдумывай разметку — заведи `Q-DEV-NNN`, реши на этапе `phase-init`/`task-init` |

**Не копируй страницы «на всякий случай».** Если требование явно не
затрагивает страницу из манифеста — она не нужна в этом проекте,
даже если выглядит полезной. Меньше кода — меньше что поддерживать.

### 2. Скопировать выбранное

- Готовые страницы → в папку админки проекта (по структуре, которую
  определяет `CLAUDE.md` стартера — не выдумывай свою)
- Общие ассеты шаблона (`assets/`) копируются **всегда целиком**,
  один раз — они не режутся по страницам (см. `planning-log.md`,
  почему: общий CSS-скелет темы, не подлежит разделению)
- Меню/навигацию админки — оставь только пункты на скопированные
  страницы плюс те, что появятся после сборки недостающих

### 3. Задокументировать сборку недостающих страниц

Создай `.docs/admin-assembly.md`:

```markdown
# Сборка страниц админки

Страницы, которых нет готовыми в шаблоне — собираются из указанных
блоков на этапе разработки (`phase-init`/`task-init`), не сейчас.
Эта команда только фиксирует план, не пишет код.

| Страница | Покрывает | Собрать из | Как |
|---|---|---|---|
| Список товаров | FR-ADM-001 | data-tables.html | Колонки: фото, название, категория, цена, статус |
| Форма товара | FR-ADM-001 | mail-compose.html | Поля ввода + загрузка фото под характеристики Товара |
```

Бери формулировки «как» из `admin-missing-pages.json`, адаптируя под
конкретные поля из `database.md` этого проекта — не общими словами.

### 4. Обновить tz-coverage.md

Для каждого `FR-ADM-*`/`FR-MGR-*`: статус `Учтено`, с пометкой —
`визуально: <page-id>` (готовая страница) или
`визуально: собрать, см. admin-assembly.md` (недостающая).

## Отчёт

- Сколько страниц скопировано, список
- Сколько страниц требует сборки — ссылка на `admin-assembly.md`
- Какие `FR-ADM-*`/`FR-MGR-*` не нашли соответствия — `Q-DEV-NNN`
- Итоговый вес папки админки в проекте
