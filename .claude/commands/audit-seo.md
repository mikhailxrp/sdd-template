## Собери список страниц для проверки, прежде чем начинать

Не проверяй одну страницу и не экстраполируй результат на весь сайт.
Собери минимум по одной странице каждого типа:

- Главная
- Категория (минимум одна с фильтром/сортировкой применённой в URL)
- Карточка товара (минимум одна)
- Страница поиска с результатами
- Страница поиска без результатов
- Статическая страница (контакты/доставка/о компании)
- Страница личного кабинета (если существует — проверь, что она
  закрыта от индексации, см. ниже)

## Проходи `dod-global.md` пункт за пунктом, с реальной проверкой

**Title/description.** Открой все собранные страницы, выпиши
`<title>` и `<meta description>` каждой в таблицу. Найди дубли между
разными страницами — это находка независимо от того, пустые они или
нет.

**Заголовки.** На каждой странице посчитай количество `<h1>` — должно
быть ровно 1. Проверь, что `<h2>`/`<h3>` не выбраны визуально (найди
в CSS/разметке случаи, где `<h3>` крупнее `<h2>` на странице, это
признак, что иерархию соблюдали для вида, не для смысла).

**Alt-атрибуты.** Пройдись по DOM каждой собранной страницы, собери
все `<img>` без `alt` или с `alt=""` там, где картинка не декоративная
(логотип, товар, баннер — не декоративная; иконка соцсети рядом с
текстовой подписью — можно декоративной).

**Контент без JS — это нужно проверить буквально, не по коду.**
Отключи выполнение JS в браузере (или сделай `curl` страницы и
посмотри raw HTML) и открой карточку товара и категорию. Текст
названия, цены, описания, характеристик должен присутствовать в
ответе сервера. Если это подгружается JS-скриптом после загрузки —
находка уровня «Высоко», не «Низко»: краулер, не исполняющий JS,
получит пустую страницу.

**schema.org/Product.** На карточке товара найди JSON-LD или
микроразметку. Скопируй её и проверь на валидность структуры (нет
пропущенных обязательных полей: name, offers.price,
offers.availability). Если разметки нет вообще на карточке товара —
находка «Высоко», это прямо влияет на то, что видно в поиске.

**Canonical.** Открой категорию с применённым фильтром
(`?sort=price&color=red` или подобное в URL). Проверь
`<link rel="canonical">` — должен указывать на базовый URL категории
без параметров. Проверь 2-3 разные комбинации фильтров одной
категории — canonical должен быть одинаковым на всех.

**sitemap.xml.** Открой `/sitemap.xml`. Проверь: не пустой, содержит
реальные URL проекта (не `example.com/page1` из заготовки стартера),
все перечисленные URL реально отвечают 200, не 404.

**robots.txt.** Открой `/robots.txt`. Сверь с ожиданиями: разделы
каталога, которые должны индексироваться, не закрыты; личный кабинет,
корзина, чекаут, админка — закрыты (`Disallow`).

**Человекочитаемые URL.** Пройдись по собранным страницам, выпиши их
реальные адреса. Если встречается `?id=`, `.php?`, числовой
идентификатор без транслитерированного названия — находка.

**Скорость ответа страницы, влияющая на индексацию.** Не полноценный
аудит производительности (это не твоя задача), но замерь время
ответа сервера (`TTFB`) для карточки товара и категории — если оно
экстремально велико (несколько секунд) при пустой/тестовой базе,
отметь это отдельно, на реальных данных будет ещё хуже.

## Особое внимание — GEO

GEO (оптимизация под ответы ИИ-систем, не только под классический
поиск) в основном пересекается с пунктами выше, но с одним отличием:
ИИ-системы чаще берут структурированные факты (цена, наличие,
характеристики), а не сплошной текст. Отдельно отметь:

- Есть ли у карточки товара чёткая, отдельно выделяемая в HTML
  структура характеристик (таблица/список пар «свойство-значение»),
  а не описание сплошным текстом, из которого факт пришлось бы
  вычленять
- Не противоречат ли друг другу разные части страницы (например,
  цена в `schema.org` и цена в видимом тексте страницы должны
  совпадать буквально — расхождение здесь хуже, чем отсутствие
  разметки вообще)

## Отчёт

Находки в формате из системного промпта.

В начале — сводная таблица: страница | title/desc уникальны | h1
корректен | alt на месте | контент без JS виден | schema.org валиден
| canonical корректен — да/нет по каждой колонке для каждой
проверенной страницы.

Отдельно: sitemap.xml и robots.txt — проверены целиком, не по
страницам, одна строка вывода на каждый.
