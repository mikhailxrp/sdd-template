## Принцип нарезки

Сначала вертикальный срез до ценности (то, что можно показать),
потом обвязка — тот же принцип, что в phase-example.md стартера.

**Приоритет из раздела 3.1 ТЗ определяет крупность фаз:**
- приоритет «срок» → тонкие фазы, MVP-ядро отдельно от остального
- приоритет «объём» → можно резать крупнее, по модулям целиком
- приоритет «бюджет» → сначала самое дешёвое к пропуску без потери
  ценности, дорогие интеграции — отдельными поздними фазами
  (проще исключить фазу целиком, чем недоделанный кусок)

**Самая рискованная интеграция — отдельной ранней фазой** (как уже
сказано в phase-example.md). Риск определяй по разделу 10.2 ТЗ:
интеграция без подтверждённого доступа/документации — самая
рискованная почти всегда.

**Порядок данных важнее порядка экранов.** Если поле появляется
в модели данных Фазы N, а становится видимым только в Фазе M > N —
это нормально и часто правильно (см. пример `vendor_id` в
sweet-ecommerce: заведено в Фазе 1, кабинет вендора — в Фазе 7,
чтобы не переписывать все запросы каталога задним числом). Не режь
фазы по экранам ТЗ буквально — режь по зависимостям данных.

## Что сделать

1. Сгруппируй заголовки требований раздела 8 (и `BR-*` раздела 9)
   в 5-12 фаз
2. Обнови `.docs/phases/_status.md`: таблица со всеми фазами,
   названием, кратким «что появляется», статус `⏳ Ожидает`
3. Если нарезка неочевидна — добавь в `_status.md` блок «Порядок не
   случайный» (по образцу sweet-ecommerce) с объяснением зависимостей
4. Допиши роадмап в `.docs/prd.md` §11 (или соответствующий раздел
   по факту структуры стартера) — списком по фазам, без детализации
   до таска (детализация — задача `phase-init`, не твоя)
5. Обнови `.docs/tz-coverage.md`: для каждого ID раздела 8 и `BR-*`
   раздела 9 укажи номер фазы

## Отчёт

- Сколько фаз, краткий список
- Обоснование нарезки (ссылка на приоритет 3.1 ТЗ)
- Какая фаза — самая рискованная и почему
- tz-coverage.md: все ли ID раздела 8/9 попали хоть в одну фазу —
  это критично, требование без фазы потеряется молча
- Готов ли проект к `sdd-modules` (если крупный, есть `.docs/modules/`
  в стартере) или сразу к `sdd-review`
