Используй только если в стартере есть `.docs/modules/` — это признак
уровня L (крупный проект с несколькими независимыми подсистемами).
Для среднего проекта (уровень M, нет папки `.docs/modules/`) этот
шаг пропускается — детализация происходит прямо в `phase-init`.

Модуль указан в аргументе: $ARGUMENTS (например `CHK` или `AI`).

Прочитай:
- `reference/sdd-planning-agent.md`
- `.docs/prd.md`, `.docs/database.md`, `.docs/phases/_status.md`
- `00-input/tz.md`, теперь уже **полностью** требования нужного
  модуля: `FR-<модуль>-*`, связанные `BR-*`, и если модуль AI —
  весь раздел 8.19 + BR-AI-001 + карточка интеграции 10.2

## Что сделать

Создай `.docs/modules/<module-lowercase>.md`: детальная спецификация
на уровне «как это работает», не «как написать код». Обычный состав:

- назначение модуля, какие роли с ним взаимодействуют
- поток данных: что откуда приходит, что куда уходит
- ключевые бизнес-правила (перескажи `BR-*`, не копируй таблицу)
- граничные случаи из сценариев ТЗ (раздел 7), которые касаются
  этого модуля — не теряй их, они уже разобраны в ТЗ, просто перенеси
- если модуль — интеграция (платёжный провайдер, ИИ, СМС): явно
  укажи поведение при недоступности (из карточки 10.2 ТЗ), это
  прямой источник для DoD будущих тасков
